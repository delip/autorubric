### Multi-Choice Criteria
- `scale_type`: "ordinal" (weighted kappa) or "nominal" (unweighted kappa)
- Options have explicit `value` (0-1) to avoid position bias
- `shuffle_options=True` (default) mitigates position bias
- NA options (`na: true`) are the structural analog of binary CANNOT_ASSESS and flow through the same `score_reports` abstain path under whichever `CannotAssessStrategy` is configured (see [Score Calculation](grading-flow.md))
- **First-class abstain channel (see [Grading Flow](grading-flow.md)).** The canonical NA option auto-injected by default is `CANONICAL_NA_OPTION` (`types.py`). The rendered list marks every NA option `(cannot assess / not applicable)` (`_render_options`/`_label_signals_na` in `prompts.py`, guarded against double-marking author NA labels), and the `MULTI_CHOICE_SYSTEM_PROMPT` NA section is unconditional.
- **Empty/refusal handling is scale-aware and option-driven.** `MULTI_CHOICE_SYSTEM_PROMPT` stays one shared constant (no `scale_type` threading, preserving the `multi_choice_system_prompt` override + prompt caching); its empty/refusal guidance directs the judge by whether any option *describes* an empty submission rather than by scale label: pick a failure / lowest-quality option when one exists (typical ordinal — the submission is **scored ≈0**, not excluded — matching "empty is a meaningful outcome") → else select the NA "cannot assess" option when no option fits an empty submission (typical nominal — flows through SKIP, **excluded**, since NA = "no applicable option") → else (forced-choice, no NA option) the closest option. This replaced the old ordinal-only "select the lowest-quality option — not NA", which was meaningless for nominal scales and contradicted the guaranteed NA channel. Both behaviors are demonstrated by worked examples (ordinal empty → lowest option; nominal empty → NA). Reconciles with the NA section: empty/refusal ("no content to evaluate") is distinct from a weak match on a non-empty submission. The **same option-driven rule** was applied to the adjacent **contradictory-submission** guidance: after the predominant/final position fails, a *genuinely ambiguous* submission resolves by option shape — ordered/quality scale → the weaker (lower-quality) reading (conservative default, scored); unordered/categorical → NA when the question genuinely can't be answered (forced-choice with no NA → the best-supported option). The multi-choice judge never sees weights (the prompt carries no `criterion_type`), so "weaker/lowest-quality" is an honest *observation* and scoring applies the weight sign downstream via option `value`.
- **Ensemble aggregation has three orthogonal knobs** — binary `aggregation`, `ordinal_aggregation`, `nominal_aggregation` — sharing a *central / conservative / permissive* axis (table below). Binary `unanimous` ≡ **min** over {0,1} option values, `any` ≡ **max**; ordinal analogs are `min` (lowest selected option) / `max` (highest). Nominal `unanimous` abstains on disagreement by selecting the criterion's **genuine NA option** (`na=True`, flows through SKIP) — never `na=True` against a real option — falling back to `mode` with a `logger.warning` only when no NA option exists.

| Concept | Binary (`aggregation`) | Ordinal (`ordinal_aggregation`) | Nominal (`nominal_aggregation`) |
| --- | --- | --- | --- |
| Central | `majority`, `weighted` | `mean`, `median`, `weighted_mean`, `mode` | `mode`, `weighted_mode` |
| Conservative | `unanimous` (≡ min over {0,1}) | `min` (lowest selected option) | `unanimous` (abstain via NA on disagreement) |
| Permissive | `any` (≡ max over {0,1}) | `max` (highest selected option) | — (unordered ⇒ no permissive analog) |

- **Tie-breaking is uniform, deterministic, and weight-sign aware.** On any tie — binary `majority` head-count / `weighted` equal-weight; ordinal/nominal `mode` count; nominal `weighted_mode` equal-weight; ordinal `mean`/`median` snap equidistance — the **score-minimizing** outcome wins (lowest `value` for weight ≥ 0, highest for weight < 0), with **lowest option index** as final tie-break (independent of judge/vote order). Binary → UNMET for weight ≥ 0 / MET for weight < 0 (via `_binary_worst_verdict`); multi-choice routes tied candidates through `Criterion.worst_option_among` (same sign-aware key as `worst_scored_option` / `FAIL`). `min`/`max` already resolve value ties to lowest index and are untouched.
