## Key Types (Quick Reference)

### Core Types (src/autorubric/types.py)

| Type | Purpose |
| --- | --- |
| `Criterion` | Single criterion: weight, requirement, optional multi-choice options. Methods: `worst_scored_option()` — score-minimizing non-NA option, weight-sign aware (canonical worst case; see [Score Calculation](grading-flow.md)); `worst_option_among(indices)` — same over a candidate subset (sign-aware key + lowest-index tie-break; single source for ensemble tie-breaking; `worst_scored_option()` delegates to it); property `na_option_index` — first NA option index or `None` (safe on binary); `with_guaranteed_na_option()` — copy with a canonical NA option **appended at end** when absent (idempotent on author NA; raises on binary) — auto-injection helper shared by grader + metrics |
| `CriterionOption` | Multi-choice option with label, value (0-1), optional `na` flag |
| `CriterionVerdict` | Enum: `MET`, `UNMET`, `CANNOT_ASSESS`. Module helper `_binary_worst_verdict(weight)` (defined beside it in `types.py`; `criterion_grader.py` imports it) — the single binary worst case: UNMET for weight ≥ 0, MET for weight < 0 — shared by the `unknown`-error path, `majority`/`weighted` tie-breaking and a decision model's `p == decision_threshold` tie; binary analog of `Criterion.worst_option_among` |
| `CriterionReport` | Criterion + verdict + reason; optional `error` (category-prefixed) + `is_error`; optional `reasoning` (see [Grading Flow](grading-flow.md)). `reason: str \| None` (required; `None` = the judge gives no explanation, see [Key Conventions](conventions.md)). Probabilistic-judge fields, both `None` for LLM judges: `probabilities: dict[str, float] \| None` — string keys so the report persists as JSON: verdict values (`"MET"`/`"UNMET"`, plus `"CANNOT_ASSESS"` when offered) for binary, `str(i)` for option index `i` in the rubric's **original** option order (never shuffled) for multi-choice; an outcome not offered is absent, not `0.0` — and `confidence: float \| None` = `clamp((K·p − 1)/(K − 1), 0, 1)` for the selected outcome (`K` outcomes offered, `p` its probability). An object pickled before these fields existed restores them at their defaults (`_setstate_with_field_defaults`) |
| `EvaluationReport` | Full grading result with score, raw_score, report, token_usage, cost |
| `EnsembleEvaluationReport` | Adds judge_scores, mean_agreement, per-criterion votes. `judge_scores: dict[str, float \| None]` — each judge's own score over the whole rubric; `None` when that judge's whole-rubric score is undefined **for its role** (undefined, never a fabricated value): a judge consulted only on some criteria (e.g. an escalation judge) is `None` on every item, even one where it happened to judge every criterion, so the entry's meaning never depends on the item; serializes as JSON `null`. No new top-level fields (the length-penalty path in `Grader.grade` rebuilds this report field by field) |
| `JudgeVote` | Single judge's verdict + reason for a criterion; optional `error` + `is_error`; optional `reasoning` (from this judge's `CriterionReport.reasoning`). `reason: str \| None`; `probabilities` / `confidence` (same scheme as `CriterionReport`, forwarded from it by `aggregate`; `None` for LLM votes); `superseded: bool = False` — recorded but not aggregated (e.g. a decision model's vote on an escalated criterion): kept for diagnostics, excluded from `agreement`. An object pickled before these fields existed restores them at their defaults (`_setstate_with_field_defaults`) |
| `MultiChoiceJudgeVote` | Single judge's multi-choice vote (ensemble); optional `error` + `is_error` (parity with `JudgeVote`); optional `reasoning`. `selected_index`/`selected_label` are `int | None` / `str | None` — `None` for a genuine no-option abstain (see [Grading Flow](grading-flow.md)); same nullability on `MultiChoiceVerdict` / `AggregatedMultiChoiceVerdict`. Same additions as `JudgeVote`: `reason: str \| None`, `probabilities` (keys `str(original option index)`), `confidence`, `superseded: bool = False` — on the base vote type, so the `multi_choice_votes` list serializes them; an older pickle restores them at their defaults (`_setstate_with_field_defaults`) |
| `EnsembleCriterionReport` | Per-criterion aggregate of judge votes; optional `error` (set only when ALL aggregated, non-`superseded` votes errored) + `is_error`. `final_reason: str \| None` (the aggregated votes' reasons joined by `_join_vote_reasons`; `None` only when no aggregated vote carried a reason — the fixed reasons `"No votes"` and binary `"All judges could not assess"` are returned whatever the votes' reasons; see [Grading Flow](grading-flow.md)). `escalated: bool = False` — the first vote (a decision model's) was judged insufficient (errored, abstained, or low `confidence`), stays in the vote list with `superseded=True`, and the final verdict, `final_reason` and `error` come from the escalation judges' votes alone, never falling back to the superseded vote (cascade report shape: [Key Conventions](conventions.md)). The `agreement` validator (`_compute_agreement`) counts only non-`superseded` votes and keeps its "recompute only when `agreement == 0.0`" rule, so round-trips stay idempotent. An older pickle restores `escalated` at its default (`_setstate_with_field_defaults`) |
| `_setstate_with_field_defaults` | Module helper in `types.py`, set as `__setstate__` on each pydantic model that has gained defaulted fields since an earlier release: `CriterionReport`, `JudgeVote`, `MultiChoiceJudgeVote`, `EnsembleCriterionReport`, and `JudgeMetrics` (`metrics/_types.py` imports it). Pydantic restores a pickle's `__dict__` exactly as stored, so a field added since would be missing and reading it would raise `AttributeError` (e.g. `compute_metrics` reads every vote's `superseded`); the helper gives each defaulted field the pickle lacks its default (`FieldInfo.get_default(call_default_factory=True)`), left out of `model_fields_set`, as validation does, so the restored object equals the same object validated today. A model that gains a defaulted field sets `__setstate__ = _setstate_with_field_defaults` (see [Key Conventions](conventions.md)) |
| `LengthPenalty` | Config: free_budget, max_cap, penalty_at_cap, exponent, penalty_type |
| `TokenUsage` | prompt_tokens, completion_tokens, total_tokens, cache stats |

### Grader Types (src/autorubric/graders/)

| Type | Purpose |
| --- | --- |
| `Grader` | Abstract base (`graders/base.py`): subclasses implement `judge(to_grade, rubric, query=None, reference_submission=None)` and `aggregate(judge_results, *, normalize=True)` — both signatures unchanged. `grade(to_grade, rubric, query=None, reference_submission=None, *, guidelines=None)`: the keyword-only `guidelines` goes to `judge` as `guidelines=` only if `judge` accepts that keyword (a `guidelines` parameter passable by keyword, or `**kwargs`); otherwise `judge` is called exactly as before and the grader warns once per instance (`UserWarning("<GraderClass> ignores rubric guidelines")`). Internal helpers: `_accepts_guidelines(target, *, through_kwargs=True)`, `_takes_guidelines` (per-instance cache `_guidelines_support`), `_warn_ignores_guidelines` (flag `_guidelines_warned`, set only after the warning is issued), `_caller_stacklevel`/`_INTERNAL_DIRS`. Rules: [Grading Flow](grading-flow.md) |
| `CriterionGrader` | Main grader - supports single judge (`judge_model_config=`, given `judge_id="default"`), ensemble (`judges=`), few-shot, and custom response formats. `llm_config=` is the deprecated alias of `judge_model_config` (last keyword-only parameter; see [Key Conventions](conventions.md)). Both keywords, and every `JudgeSpec`, take `LLMConfig \| DecisionModelConfig`, alone or mixed in one ensemble. Construction builds one client per judge into two maps keyed by `judge_id` — `_clients: dict[str, LLMClient]` (LLM judges only, so tests that swap LLM clients are unaffected) and `_decision_clients: dict[str, DecisionModelClient]` — so a missing SDK (`ImportError`), a missing API key, a key the SDK would reject, or a resolved base URL (`api_base` or `TYPESAFE_BASE_URL`) that is not an absolute http(s) URL free of whitespace and control characters (`ValueError`), or an environment in which `httpx2` cannot build an HTTP client (TLS/proxy settings), fails there, not per item; an `api_base` or `extra_headers` entry HTTP does not allow already fails in `DecisionModelConfig` itself. `few_shot_config` or `training_data` when every judge is a decision model → `ValueError` ("few-shot examples apply to LLM judges only"); with at least one LLM judge, `_prepare_examples` selects examples for the LLM judges alone. `binary_response_format`/`multi_choice_response_format` with any decision-model judge → `ValueError`; `system_prompt`/`multi_choice_system_prompt`/`shuffle_options` passed while every judge is a decision model → one `UserWarning` each (`shuffle_options` keeps its plain `True` default; `__init__` is wrapped by `_records_passed_keywords`, which records the passed keyword names in the context variable `_PASSED_KEYWORDS`). `judge(to_grade, rubric, query=None, reference_submission=None, *, guidelines=None)` accepts rubric guidelines (so `Grader.grade` forwards them) and threads them to both judge kinds: the `GUIDELINES_BLOCK` in front of every LLM user prompt, the first field of a decision model's state. `escalation: EscalationConfig \| None = None` (keyword-only, before the deprecated `llm_config`) makes it a confidence cascade: exactly one decision-model primary judge, LLM escalation judges, `judge_id`s unique across both → else `ValueError`; the grader stores its own re-validated copy `_escalation = dataclasses.replace(escalation)` (an in-place change to the config's list or dict before construction is validated, one after it never reaches the grader), and `_escalation_judges` is a property reading that copy's `judges` (`[]` without a cascade), kept apart from `_judges`; escalation judges count as judges for the clients, few-shot examples and the LLM-only settings. Class-level defaults `_escalation = None` and `_escalation_names_warned = False` give a grader whose `__init__` never ran (an init-skipping subclass, an older pickle) no cascade. `judge_ids` property: `list[str]` of `_judges` then `_escalation_judges` (what `EvalRunner` shows in detailed progress). `is_ensemble` is `len(_judges) > 1` (a cascade is not an ensemble). Private `_check_escalation_names(rubrics, where) -> bool` warns about unknown `per_criterion` names; the module function `_escalation_names_checked(grader, dataset)` runs that check once for a batch (`EvalRunner.run`, `fill_ground_truth`) and returns the context that sets `_ESCALATION_NAMES_CHECKED` while it grades. Per-judge dispatch, one request per item, mixed ensembles, the cascade, the LLM-only settings, guidelines, failure scope and billing: [Grading Flow](grading-flow.md) |
| `EscalationConfig` | Exported (`autorubric` and `autorubric.graders`; defined in `graders/criterion_grader.py` beside `JudgeSpec`, which it holds) frozen `@dataclass` configuring a confidence cascade, the grouped-config pattern of `FewShotConfig`/`LengthPenalty`/`CannotAssessConfig`. Fields `judges: list[JudgeSpec]`, `threshold: float`, `per_criterion: Mapping[str, float] \| None = None`. A hand-written `__init__(judges: LLMConfig \| Sequence[JudgeSpec], threshold, per_criterion=None)` validates (`ValueError`, message style of `DecisionModelConfig`): a bare `LLMConfig` becomes `[JudgeSpec(config, "escalation")]`; a list or tuple must be non-empty `JudgeSpec`s of LLMs (a `DecisionModelConfig`, bare or in a spec, is refused, naming the offending `judge_id`s); `threshold` and every `per_criterion` value a real number in [0, 1] (`_is_real_number`: no `bool`, NaN fails the range); `per_criterion` a mapping with `str` keys (criterion names), copied into a `dict`. Frozen (fields cannot be reassigned; stored through `object.__setattr__`), though the stored list and dict can change in place, which is why `CriterionGrader` keeps its own copy; `dataclasses.replace` validates again (and copies both containers); `repr`/`__eq__`/`fields()` are generated. `threshold_for(criterion) -> float`: the `per_criterion` value for the criterion's **name**, else `threshold` (always `threshold` for an unnamed criterion). A criterion is escalated when the decision model's vote errored, abstained, or has `confidence < threshold_for(criterion)` (flow: [Grading Flow](grading-flow.md)) |
| `JudgeSpec` | Ensemble judge config: llm_config, judge_id, weight. `llm_config: LLMConfig \| DecisionModelConfig` — the config's type is the judge's kind — stays the **stored dataclass field** (never renamed), with `judge_model_config` as a read/write property over it (same type; both `@overload`s take either kind). A hand-written `__init__` (typed by two `@overload`s; `dataclasses.MISSING` sentinels tell a missing argument from an explicit `None`) accepts the unchanged positional form `JudgeSpec(config, judge_id, weight=1.0)`, `llm_config=` (no warning) and `judge_model_config=` (preferred); both → `ValueError`, a missing config/`judge_id` → `TypeError` worded like Python's own. `fields()`/`asdict()`/`repr`/`__eq__`/`__match_args__`/`replace()` (which takes `llm_config=`)/pickles are unchanged — pinned by fixtures captured from the pre-alias library in `tests/golden/legacy/` |
| `CriterionResult` / `JudgeCriterionResults` | Internal per-judge carriers `aggregate` consumes: `CriterionResult(report, usage=None, cost=None)` and `JudgeCriterionResults(judge_id, weight, criterion_results, role="primary")`. `criterion_results: list[CriterionResult \| None]` is always full-length (one entry per criterion of the effective rubric); `role: Literal["primary", "escalation"]` — a primary judge has a result everywhere, a cascade's escalation judge only at escalated criteria and `None` elsewhere. `reports` (the judged criteria's reports, in order) / `total_usage` / `total_cost` (sums of the non-`None` entries, `None` when there are none) skip `None` cells. Module helper `_escalates(report, threshold) -> bool`: `is_error` or `is_na` or `confidence is None` or `confidence < threshold`. `usage`/`cost` belong to the call that produced a result: one per criterion for an LLM judge; for a decision-model judge the item's single request rides on `criterion_results[0]` (the rest carry `None`), so the totals are per-item for either kind |
| `_failed_judgment_result` | Internal helper `(criterion, judge_id, error, *, shuffle_order=None) -> CriterionResult`: the single source of failure reports for both judge kinds (classification, the warning log, the verdict and the report). Routing: [Grading Flow](grading-flow.md) |

Note: `FewShotConfig` is listed in the Core Types table above (defined in `src/autorubric/types.py`). `EscalationConfig` is listed here because it is defined in `graders/criterion_grader.py` (it holds `JudgeSpec`s; `types.py` cannot import the grader module).

### Rubric Type (src/autorubric/rubric.py)

| Type | Purpose |
| --- | --- |
| `Rubric` | `Rubric(rubric: list[Criterion], *, guidelines: str \| None = None)` — the first parameter keeps its name `rubric`; `guidelines` is keyword-only. Attributes: `rubric` (the criteria, in order) and the `guidelines` property: free text that applies to every criterion (grading conventions, definitions, audience, scale anchors), `None` when absent. `_normalize_guidelines` (`utils.py`, shared with `Grader.grade`, `CriterionGrader.judge`, the prompt builders and `build_state`, so blank means none everywhere): blank text (empty or whitespace only) means no guidelines and is stored as `None`, the single "absent" value every consumer checks; any other text is kept verbatim (never stripped); a non-`str` raises `TypeError`; the setter applies the same rules; a class-level `_guidelines = None` makes a `Rubric` pickled before guidelines existed read as `None`. No `__eq__`/`__repr__`/serializer of its own (`copy`/`deepcopy`/pickle keep `guidelines`). Methods: `grade` (passes `guidelines=` to `grader.grade` only when set, and only to a `grade` that accepts it — see [Grading Flow](grading-flow.md)), `compute_score`, and the loaders `from_dict`/`from_json`/`from_yaml`/`from_file`. Each loader builds through the private `_from_data(data)`, never through `cls.from_dict` (as before guidelines existed): the criteria come from `cls.validate_and_create_criteria(data)`, the public parse hook, so a subclass override of it applies to every loader (it returns the criteria only, and validates guidelines as the loaders do); the guidelines come from `_rubric_guidelines(data)`, which reads only a dict's `"guidelines"` key and, when its `"rubric"` value is a dict, that dict's own, whatever else the data holds (a subclass's own format carries guidelines the same way; a list carries none). `cls(criteria)` is called exactly as before when there are no guidelines. With guidelines, `cls(criteria, guidelines=...)` is called only when `cls`'s `__init__` declares a `guidelines` parameter that can be passed by keyword (`_accepts_guidelines(cls, through_kwargs=False)`), and that `__init__` decides what they become. `**kwargs` does not count, unlike for `judge` (which has no other channel): an `__init__(self, rubric, **options)` may predate guidelines and would reject the keyword or keep it as an option of its own. Every other subclass (e.g. `__init__(self, rubric)`, `**kwargs`, one that skips `Rubric.__init__`) is built with `cls(criteria)` as before and then given them through the `guidelines` property, which replaces any guidelines its `__init__` supplies when given none; so no subclass receives a keyword it does not declare, and each loads every rubric file, with or without guidelines, and honours them (`TestSubclassLoading` in `tests/rubric/test_rubric_guidelines.py`). `_criteria_entries` reads a dict's `"sections"` list, else its `"criteria"` list. Formats: a list (criteria and/or sections, a section being a dict with a `"criteria"` list); `{"sections": [...]}`; `{"criteria": [...]}` (new; a top-level `"criteria"` key used to raise); `{"rubric": list \| {"sections" \| "criteria": [...]}}`. Any dict form may carry `"guidelines"` (a string, or `null` for none), beside or inside `"rubric"` but not both (`ValueError`); a non-string raises `ValueError` (`_guidelines_field`); key precedence `"rubric"` > `"sections"` > `"criteria"` is unchanged and other keys are ignored. Behaviour change for one edge case: a `{"sections"\|"rubric": ..., "guidelines": ...}` file used to load with `"guidelines"` silently ignored; it is now honoured. On disk (`RubricDataset._serialize_rubric`, improvement-loop artifacts): `{"guidelines": ..., "criteria": [...]}` only when `guidelines` is set, the list form otherwise |

| `RubricDataset` | optional prompt, optional global rubric, items, name, optional reference_submission; methods: get_item_rubric (precedence unchanged: the item's own rubric, guidelines included, else the global one), get_item_prompt, get_item_reference_submission, split_train_test (both splits share the same `Rubric` objects, so `guidelines` survive), to/from_file. ### Decision-Model Types (src/autorubric/decision.py)

| Type | Purpose |
| --- | --- |
| `DecisionModelConfig` | Exported dataclass configuring a decision-model judge (TypeSafe's Jev or any System One-compatible endpoint). Fields, in order: `model` (required; the only positional field, the rest are keyword-only via `KW_ONLY`), `api_key=None` (→ `TYPESAFE_API_KEY`; kept out of `repr`), `api_base=None` (→ `TYPESAFE_BASE_URL` → `https://api.typesafe.ai`), `timeout=60.0` (each HTTP operation; a request's wait for its turn is not timed), `max_retries=3` (total attempts), `max_parallel_requests=None` (no shared limit: each judge then keeps at most `_DEFAULT_CONNECTIONS` = 100 requests in flight per event loop; a limit sizes its HTTP connection pool, so one above 100 is honoured), `cache_enabled=False`, `cache_dir=".autorubric_cache"`, `cache_ttl=None`, `extra_headers={}` — the names and defaults of these shared concepts equal `LLMConfig`'s — then `binary_framing: BinaryFraming = "noul_framed"`, `ordinal_framing: OrdinalFraming = "choice"`, `decision_threshold=0.5` (P(MET) cut for the Noul framings; exact tie → weight-sign worst case), `input_cost_per_token=None` (no built-in price table; unset → cost unknown, contributes nothing to `completion_cost`). `__post_init__` raises `ValueError` for an empty `model`, an unknown framing, a `decision_threshold` outside [0, 1] (or a bool/NaN), a non-positive or non-finite `timeout`, a `max_retries` or `max_parallel_requests` that is not an int ≥ 1, a non-finite `max_retries * timeout` (it sets the retry budget), a `cache_ttl` ≤ 0, a negative or non-finite price, an `api_base` that is not an absolute http(s) URL or that contains whitespace or a control character, a query or fragment, or credentials (`_check_base_url`; `_shown_url` never repeats a URL holding an `@` in the message), `extra_headers` that is not a mapping of `str` names to `str` values (the SDK would reject such a header inside every request, as an `unknown` error, i.e. the worst case on every criterion; the message names only types, never a header value), or an `extra_headers` name that is not an RFC 9110 token (`_HTTP_FIELD_NAME`) or value that is not an RFC 9110 field value — visible ASCII, spaces or tabs only between characters (`_HTTP_FIELD_VALUE`), or that names, in any letter case, a header the SDK sets itself and would overwrite (`_SDK_OWNED_HEADERS`: `Authorization`, `Accept`, `Content-Type`, `User-Agent`, `X-TypeSafe-SDK`, `X-TypeSafe-Runtime`, `X-TypeSafe-Retry-Count`; for `Authorization` the message points to `api_key`) — unlike `LLMConfig`'s, these `extra_headers` cannot override the transport's own headers; the message names the header, never its value. Why each is checked here: [Key Conventions](conventions.md). Constructing it never imports the SDK (nor `httpx2`: whether the SDK's HTTP stack can encode the host is checked when the client is built). Client, cache, rate-limit and cost semantics: [Key Conventions](conventions.md) |
| `BinaryFraming` / `OrdinalFraming` | `Literal["noul", "noul_framed", "choice"]` / `Literal["choice", "score"]` — how a binary / ordinal multi-choice criterion is posed (nominal criteria are always Choice). Only binary `"choice"` can abstain (`CANNOT_ASSESS`); `"score"` never offers the NA option, so a Score-framed criterion cannot abstain |
| `build_state` / `build_question` / `build_questions` / `question_id` | Internal (not exported) request builders: `build_state(to_grade, *, query=None, reference_submission=None, guidelines=None) -> dict[str, str]` (fields `guidelines` (not blank), `input`, `reference_submission`, then `submission` — or `thinking` + `output` when `to_grade` holds a section per `_has_thinking_output_sections` in `utils.py`); `build_question(criterion, config, state) -> Noul \| Choice \| Score` (raises `ValueError` for an inexpressible criterion); `build_questions(rubric, config, state) -> (dict[str, Question], dict[int, ValueError])` over the effective rubric, ids `question_id(criterion_idx)` = `"c{criterion_idx}"`, inexpressible criteria left out with a per-index error. Framing text: the `DECISION_MODEL_*` constants in `prompts.py`. Rules: [Grading Flow](grading-flow.md) |
| `answer_to_report` / `selection_confidence` | Internal answer mapping: `answer_to_report(criterion, criterion_idx, answers, config) -> CriterionReport` (verdict or `MultiChoiceVerdict`, `probabilities`, `confidence`, `reason=None`, `reasoning=None`; `ValueError` for a missing, wrong-typed or malformed answer → `parse`); `selection_confidence(p_selected, n_outcomes) -> float` = `clamp((K·p − 1)/(K − 1), 0, 1)` (`ValueError` for `K < 2` or `p` outside [0, 1]). Rules: [Grading Flow](grading-flow.md) |
| `DecisionModelClient` | Internal (not exported) counterpart of `LLMClient`: `system_one(state, questions, *, use_cache=None) -> SystemOneResponse`, static `token_usage(response) -> TokenUsage`, `completion_cost(response) -> float \| None`, read-only `base_url` / `host` / `rate_limit_key`, `close()` (the disk cache) and a sync context manager. Construction raises `ImportError` (message: `pip install 'autorubric[typesafe]'`) when the SDK is missing and `ValueError` without an API key, with a key the SDK would reject (`_is_valid_api_key`: printable ASCII, no whitespace) or with a resolved base URL (`api_base` or `TYPESAFE_BASE_URL`) that is not an absolute http(s) URL free of whitespace and control characters, query, fragment and credentials (`_check_base_url`), or whose request URL `base_url + _SYSTEM_ONE_PATH` the SDK's HTTP stack refuses (`_check_request_url`: `httpx2.InvalidURL`, e.g. a host that is not a valid IDNA name); and, in an environment in which `httpx2` cannot build an HTTP client (`_new_http_client`, built once and dropped: e.g. `SSL_CERT_FILE` naming a missing file, a SOCKS proxy without `socksio`), `httpx2`'s own exception with an `add_note` naming the model and the TLS/proxy settings to check. An environment that breaks after construction fails a request with `TypeSafeAPIConnectionError` (`infrastructure`) before it is sent. A request waits for the host's `RateLimitPool` semaphore, then for one of its SDK client's connection slots (`_lease_sdk_client`), before the SDK sends it, so the wait counts against neither its timeout nor its retry budget. Details: [Key Conventions](conventions.md) |

### Metrics Types (src/autorubric/metrics/)

| Type | Purpose |

| `MetricsResult` | accuracy, precision, recall, f1, kappa, correlations, bias, per_criterion. See [Undefined → None](metrics.md) |
| `PooledScaleMetrics` | Pooled rubric-point metrics for ONE scale type on a per-item heterogeneous-rubric dataset (e.g. HealthBench), in `MetricsResult.pooled_by_scale`. Binary-only categorical block (`None` for ordinal/nominal — undefined across differing option sets): `kappa`/`phi`/`precision`/`recall`/`f1` (`float | None`) and `confusion_matrix: ConfusionMatrix | None`. Frozen |
| `CriterionMetrics` | Per-criterion binary metrics (+ optional inter-judge agreement: `krippendorff_alpha`, `fleiss_kappa`). `accuracy`/`precision`/`recall`/`f1`/`kappa` are `float | None` (`None` when no usable paired samples — counts `support_*`/`n_samples` stay `0` — or kappa undefined). Adds `confusion_matrix: ConfusionMatrix | None` (2×2 `["MET","UNMET"]`, `None` when no samples), `fpr`/`fnr`/`phi` (φ = Matthews correlation coefficient) all `float | None`, `is_degenerate: bool` (True iff `n_samples > 0` but `kappa is None`), and `coverage_stats: CoverageStats | None` |
| `OrdinalCriterionMetrics` | weighted_kappa, adjacent_accuracy, correlations, optional `krippendorff_alpha` (ordinal-aware) + `fleiss_kappa`. `exact_accuracy`/`adjacent_accuracy`/`weighted_kappa`/`rmse`/`mae` are `float | None`. `confusion_matrix` is now a `ConfusionMatrix` (its `.labels` carry the former `option_labels`; the separate `option_labels` field is removed). Adds `is_degenerate: bool` (True iff `n_samples > 0` but `weighted_kappa is None`) and `coverage_stats: CoverageStats | None` |
| `NominalCriterionMetrics` | kappa, per_option metrics, optional `krippendorff_alpha` + `fleiss_kappa`. `exact_accuracy`/`kappa` are `float | None`; `OptionMetrics.precision`/`recall`/`f1` likewise `float | None`. Same migration: `confusion_matrix: ConfusionMatrix` (labels in `.labels`, `option_labels` removed). Adds `is_degenerate: bool` (keyed on `kappa is None`) and `coverage_stats: CoverageStats | None` |
| `ConfusionMatrix` | Unified labelled confusion matrix shared by binary / ordinal / nominal / per-judge / held-out diagnostics. Fields `matrix: list[list[int]]` (rows=true, cols=pred) + `labels: list[str]`. Properties `n_classes`/`total`; binary-only `tp`/`fp`/`fn`/`tn` and the derived rates `precision`/`recall`/`fpr`/`fnr` (each `float | None`, `None` at a zero denominator) — these raise `ValueError` unless the matrix is 2×2 with `labels[0] == "MET"`. Label conventions: binary `["MET","UNMET"]`; per-judge binary `["MET","UNMET","CANNOT_ASSESS"]`; multi-choice = option labels (+ `"NA"` last when an abstain class is present) |
| `CoverageStats` | How much of the raw paired sample survived abstention/error exclusion (only under the `exclude` handling mode). `n_total`/`n_covered`/`n_errored` are `int`; `coverage`/`judge_abstain_rate`/`gt_abstain_rate`/`union_exclusion_rate`/`error_rate` are `float | None` (undefined → None when `n_total == 0`) |
| `JudgeMetrics` | Per-judge mirror of the aggregate (precision/recall/f1 binary MET-vs-rest → `None` for multi-choice-only). Adds `phi: float | None` (per-judge MCC on {MET, UNMET}) and `confusion_matrix: ConfusionMatrix | None` (per-judge, pooled across criteria from raw pre-filter codes; 3×3 with `CANNOT_ASSESS` abstain class last; `None` when no data). Score-level fields `score_rmse`/`score_mae` (`float \| None`), `score_spearman`/`score_kendall`/`score_pearson` (`CorrelationResult \| None`) and `bias` (`BiasResult \| None`) are all `None` when the judge has no defined `judge_scores` entry on any item; otherwise they use only the items where the entry is defined. A `None` entry comes only from the report (a judge consulted only on some criteria); a judge whose every vote on an item failed keeps the float entry its abstentions or worst cases scored, as it always has. Judges with every score defined always get non-`None` values. Adds `coverage: Literal["full", "escalated"] = "full"` (`"escalated"` by role: every `judge_scores` entry `None`, a cascade escalation judge measured on its escalated subset) and `n_pairs: int \| None = None` (for `"escalated"`: the subset's (item, criterion) pairs with a genuine vote and ground truth of the criterion's type, before abstention handling); a wrap `model_serializer` omits both from dumps while at their defaults, and an older pickle restores them at their defaults (`_setstate_with_field_defaults`) — see [Metrics](metrics.md) |
| `NAStats` | NA diagnostics for multi-choice criteria: `na_count_true`, `na_count_pred`, `na_false_positive`, `na_false_negative`, `na_kappa` (Cohen's kappa on dichotomized {NA, not-NA}, pred vs truth) + Landis & Koch `na_kappa_interpretation`. `na_kappa`/`na_kappa_interpretation` `None` when undefined (no paired NA, single class, NaN) |
| `CannotAssessStats` | CANNOT_ASSESS diagnostics for **binary** criteria — binary parallel of `NAStats`: `ca_count_true`, `ca_count_pred`, `ca_false_positive`, `ca_false_negative`, `ca_kappa` (Cohen's kappa on dichotomized {CANNOT_ASSESS, not-CANNOT_ASSESS}, pred vs truth) + `ca_kappa_interpretation` (`None` when undefined). A **distinct kind of abstention** from NA, so a separate type — see [CANNOT_ASSESS Handling (binary metrics)](abstention.md) |
| `CannotAssessMode` | `Literal["exclude", "as_unmet", "as_category"]` — how binary CANNOT_ASSESS verdicts are handled at metrics time. See [CANNOT_ASSESS Handling](abstention.md) below |
| `NAMode` | `Literal["exclude", "as_unmet", "as_category"]` — multi-choice NA analog of `CannotAssessMode`. See [NA Handling (multi-choice metrics)](abstention.md) below |
