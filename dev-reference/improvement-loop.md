### Improvement Loop Artifact Persistence
When `save_artifacts=True` and `artifacts_dir` is set, the improvement loop writes:
- `rubric-iter-{NN}.json` — the iteration's rubric: the criteria array (`weight`, `requirement`, `name` when set, and for a multi-choice criterion its scale — `scale_type`, `options`, `aggregation` when set — as `RubricDataset` files record it, `_criterion_scale_data` in `dataset.py`), or `{"guidelines": ..., "criteria": [...]}` when the rubric has guidelines (`_save_rubric` via `_rubric_artifact_data`, `_rubric_criteria_data(rubric, with_scales=True)`; `Rubric.from_dict` reads either back, options included)
- `eval-iter-{NN}.html` — meta-rubric eval report (always generated, regardless of `display`)
- `iter-{NN}.json` — rich per-iteration JSON (quality report, issues, validation samples, revision prompts/response; each sample's `"submission"` and each exemplar's `submission_snippet` are `_content_preview(submission)`, cut to 200 characters wherever they were cut before (every snippet; a ground-truth or held-out sample, not an agreement sample): text unchanged, an image as `[image: <name>]`, so a validation set holding images writes JSON; `validate_agreement` takes `samples: Sequence[Content]`; `TestValidationItemsHoldingImages` in `tests/meta/test_improve.py`); its `rubric_criteria` is always the criteria array (`_rubric_criteria_data(..., with_scales=True)`, multi-choice scales included)
- `improvement_report.html` — consolidated report (always generated, regardless of `display`); its Final Rubric panel shows the guidelines, HTML-escaped, above the criteria table when the final rubric has them
- `summary.json` — full run metadata, config snapshot, per-iteration summary; `original_rubric`/`final_rubric` use the same form as `rubric-iter-{NN}.json`

A rubric without guidelines produces exactly the artifacts it did before guidelines existed, and a binary criterion's entry is unchanged by `with_scales`. The `meta_rubric` revision prompt (`revise_rubric`) shows the criteria without their scales (`_rubric_criteria_data` with the default `with_scales=False`), so it is unchanged. The held-out revision prompt (`revise_rubric_held_out`) shows a multi-choice criterion's scale: for a rubric with one, `original_criteria` is `_rubric_criteria_data(rubric, with_scales=True)` and the user prompt starts with `HELD_OUT_REVISION_SCALES_BLOCK` (`prompts.py`; after the guidelines block, for custom `revision_user_prompt_template`s too), which tells the LLM the options are fixed and not part of its output, to keep each multi-choice requirement a question its options answer, and that the FP/FN rates (`n/a`) are binary only. Without it the LLM, which sees diagnostics naming options, could rewrite an option question as a binary statement that the carried-over options then no longer answer. A binary-only rubric's held-out prompt is unchanged (`TestRevisionKeepsTheOptions`); the `revise_rubric_held_out` entries of the meta-prompt goldens, whose rubric has a multi-choice criterion, were recaptured for this (before, held-out validation raised on any multi-choice label, so the loop never sent that prompt).

`revise_rubric()`, `validate_agreement()`, `validate_ground_truth()` accept a private `_capture` parameter for artifact collection.

### Rubric Guidelines in Meta-Rubric Evaluation and the Loop

The meta-judge has the general grading system prompt, so its instruction (`_meta_judge_instruction(rubric, *, in_context=False)`) opens with `_RUBRIC_SUBJECT_INSTRUCTION`, saying the submission is the rubric and no response is part of it, and in context `_TASK_PROMPT_INSTRUCTION`. Without them judges faulted a rubric for holding no response.

`Rubric.guidelines` (see [Type Catalog](types.md)) is rubric text that applies to every criterion, so the meta paths treat it as part of the rubric:

- **Meta-judge.** `evaluate_rubric_standalone`/`evaluate_rubric_in_context` build the rubric under review with `_rubric_for_meta_judge`: `{"guidelines": ..., "criteria": [...]}` (guidelines first, as on disk) when present, `{"criteria": [...]}` otherwise. `_meta_judge_instruction` appends `_GUIDELINES_REF_INSTRUCTION` (what the field is, the rule judges get — the criterion text governs, the guidelines clarify how to apply it — and to assess each criterion as a rater would apply it with the guidelines) to `_CRITERIA_REF_INSTRUCTION` only when present. The display summary (`_rubric_summary`) reads "... criteria and guidelines".
- **Carry-over.** The revision LLM writes criteria only, so `revise_rubric`/`revise_rubric_held_out` rebuild the revised rubric with `_revised_rubric`, which carries the input rubric's guidelines unchanged. Without it every iteration after the first would grade and be meta-evaluated without them. A held-out revision that breaks the criteria structure returns the input rubric, guidelines included. A held-out revision also carries each criterion's scale (`options`, `scale_type`, `aggregation`, by position: the structure check has kept count, order and names) from the input rubric, whatever the LLM wrote: the ground truth's labels name those options, so they must resolve on every iteration's rubric, and the LLM may change wording and weights only (`TestRevisionKeepsTheOptions`, `TestTheLoop` in `tests/meta/test_held_out_multi_choice.py`).
- **Revision prompt.** The loop never revises guidelines. The revision LLM still sees them, read-only, because correctness needs it: the issues and diagnostics it must act on come from judges that saw the guidelines and can refer to them, and a criterion revised blind could contradict them — a conflict the criterion text wins when grading. `_with_guidelines_block` puts `RUBRIC_REVISION_GUIDELINES_BLOCK` (`prompts.py`; the guidelines verbatim, then "They are fixed and not part of your output: revise only the criteria, and keep them consistent with the guidelines.") at the start of the user prompt, for both strategies and for custom `revision_user_prompt_template`s; the system prompt is unchanged.
- **Byte identity.** Without guidelines every meta-judge and revision prompt is unchanged. `tests/meta/test_meta_prompt_goldens.py` pins them: `tests/golden/meta/without_guidelines.json` was captured from the unmodified library, `with_guidelines.json` pins the guidelines case.

### Validation and Items With No Score

In ground-truth mode the loop compares each validation item's graded score with its expected score. `compute_expected_scores(validation_data) -> list[float | None]` is each item's `Rubric.compute_score(ground_truth)` under the dataset rubric, `None` where the ground truth leaves nothing to score (every label abstains under `SKIP`). `validate_ground_truth(rubric, validation_data, expected_scores: Sequence[float | None], grader, ...)` grades every item and (#18):

- raises `RuntimeError("Ground-truth validation grading failed for item <i> (no score): <error>")` on a failed grade (report `error` set, e.g. `"Every criterion's judgment failed: ..."`), since a correlation or MAE over a fabricated fallback would be meaningless (`test_a_failed_grade_stops_the_validation`);
- leaves out of the comparison an item with no score to compare — nothing left to score in its grade (`score` `None`, no `error`) or in its ground truth (expected score `None`) — and out of `_item_reports`, which stays aligned with the returned `(rubric_score, expected_score)` pairs that `format_ground_truth_for_prompt` reads;
- returns Spearman ρ over three or more compared items (`None` for a constant array), `1 − MAE` over one or two, and `None` ("not measured", as `pareto_accept`/`_check_convergence` read it) when no item was compared (`TestValidateGroundTruthWithoutAScore` in `tests/meta/test_improve.py`).

`_capture` still records every item, so the ground-truth `validation_samples` of `iter-{NN}.json` hold `rubric_score`, `expected_score` and `gap` as `null` where undefined (`gap` whenever either score is).

In multi-judge mode, `validate_agreement` leaves out a sample whose grade failed (report `error` set): its stand-in votes agree with one another but measured nothing, so neither `mean_agreement` nor its criteria's `agreement` enter the means; its cost still counts (`TestValidateAgreementFailedGrades`).

Without a quality score the loop cannot go on, and `ImprovementRunner` says why: a failed meta-rubric quality evaluation (report `error` set) raises `RuntimeError("Meta-rubric quality evaluation failed (no score): <error>")`; one whose every meta-criterion abstained under `SKIP` (no score since #18, no error) raises `RuntimeError("Meta-rubric quality evaluation has no score: the meta-judge could assess none of the meta-rubric's criteria, so nothing was left to score")` (`test_a_quality_evaluation_without_a_score_stops_the_run_and_says_why`).

### Held-Out Validation Diagnostics

`validate_held_out()` grades held-out items and compares per-criterion verdicts against ground truth. Labels are read with `resolve_ground_truth`, for every item before the first is graded, so a bad label, an item without `ground_truth`, or a `ground_truth` list whose length differs from the rubric's criteria count (silently truncated before) raises `ValueError` before any call: a binary label as a verdict, a multi-choice label as an option index among the options of `Criterion.with_guaranteed_na_option()` (so `CANONICAL_NA_OPTION`'s label, which `fill_ground_truth` records, resolves; #38). A binary judgment agrees with its label when the verdicts match; a multi-choice judgment (`extract_all_verdicts_from_report`'s `selected_index`) when the judge chose the labelled option. Beyond accuracy / FP-rate / FN-rate, each `CriterionErrorReport` carries:

- `kappa` — Cohen's kappa between judge and ground truth over the usable pairs, or `None` when undefined (e.g. a constant array). Never a fabricated `0.0`. Binary: on the MET/UNMET labels (via `_kappa_or_none`); multi-choice: the scale's kappa as `compute_metrics` computes it, quadratic-weighted for ordinal, unweighted for nominal (`_compute_ordinal_criterion_metrics`/`_compute_nominal_criterion_metrics`, which also give the multi-choice accuracy and matrix).
- `coverage` — fraction of ground-truth-paired items that yielded a usable (non-abstained) verdict, over the **raw pre-exclusion** per-criterion denominator; `None` when nothing was paired.
- `ca_rate` — fraction of those raw paired items on which the judge or the ground truth abstained (CANNOT_ASSESS; on a multi-choice criterion an NA option, or a judge's abstention without one), same denominator; `None` when nothing was paired.
- `confusion_matrix` — a `ConfusionMatrix` (reused from `autorubric.metrics`, rows=true cols=pred) over the usable verdicts: 2x2 MET/UNMET (`labels=["MET","UNMET"]`) for a binary criterion; over the option labels for a multi-choice one, with the added NA option appended only when a judged cell's judgment or label names it (or a judge abstained without an option), as `compute_metrics` reconstructs the effective criterion. `None` when there are no usable samples (so a constructed all-zero matrix never masquerades as data).

`false_positive_rate`/`false_negative_rate` are `float | None`: `None` for a multi-choice criterion, which has no positive class (a binary criterion's stay `0.0` when their denominator is empty, as before). `CriterionExemplar.llm_verdict`/`ground_truth_verdict` are `CriterionVerdict | str`: a multi-choice exemplar names the options by label, after the `cannot_assess` handling. `format_held_out_for_prompt` writes a label as it is and an undefined rate as `n/a` (`_verdict_text`/`_rate_text`); binary-only diagnostics, prompt text, HTML and `iter-{NN}.json` are byte-identical to before (`tests/meta/test_held_out_multi_choice.py` covers the multi-choice cases).

`HeldOutValidationResult` records `cannot_assess` (the handling mode in effect), plus `mean_coverage` / `mean_ca_rate` rolled up from the per-criterion values via `_mean_or_none` (None-skipping).

**Failed grades and failed criteria.** An item whose grade failed (report `error` set, e.g. `"Every criterion's judgment failed: ..."`) has no usable verdict: as an errored item in `compute_metrics`, it counts in each criterion's raw denominator, so `coverage` and `ca_rate` drop, and in no tally, abstention count, kappa or exemplar. A criterion whose judgment failed on an item otherwise graded (`_judgment_failed`, a failed cell in `compute_metrics`) is handled the same way for that criterion, under every `cannot_assess` mode: its stand-in `CANNOT_ASSESS` is no abstention of the judge's, and an `unknown` failure's worst case no prediction, so neither enters `ca_rate`, the confusion tallies, kappa or the exemplars, where a "Judge call failed" reason would send the revision after a criterion nothing misjudged (`TestHeldOutFailedGrades` in `tests/meta/test_held_out_diagnostics.py`).

**Validation items holding images.** A validation submission that holds images is graded with them (the grader loads them, as for any grade), but everything the loop writes or shows the revision LLM is text: each `"submission"` artifact field and every `CriterionExemplar.submission_snippet` is `_content_preview(...)` (`content.py`), `[image: <name>]` where a file-backed image was and `[image: <N> bytes]` for a bytes-backed one, so `format_held_out_for_prompt`'s `Submission:` lines show the markers. This is a known limitation: the revision LLM (`revise_rubric`, `revise_rubric_held_out`) never sees the pixels, only the markers and the judges' reasons, so it revises criteria about image content from what the judges wrote. The meta-judge sees the rubric and the `task_prompt` string, never a submission, so it is unaffected; a dataset `prompt` holding images reaches the judges as the grade's `query`, never the revision LLM. Documented for users in `docs/api/meta-improvement.md`.

**Abstention handling.** `ImprovementConfig.cannot_assess: CannotAssessMode` (default `"exclude"`, preserving the prior silent-exclude behavior) threads from the held-out runner into `validate_held_out`, which passes it as `mode=` to `filter_cannot_assess` for binary criteria and as `na_mode`'s value to `filter_na_multi_choice` for multi-choice ones (NA is the structural analog of CANNOT_ASSESS). `"exclude"` drops abstained pairs from the confusion tallies; `"as_unmet"` folds CANNOT_ASSESS into UNMET, and NA into `Criterion.worst_scored_option()`; `"as_category"` keeps it as a distinct label, so an NA judgment on an NA label agrees. `"as_category"` is refused (`ValueError`, before any call, `_refuse_ordinal_na_category`) for an ordinal criterion on which NA can occur — the judge is shown an NA option (`grader._effective_criterion`, read with `getattr`; a grader without it, i.e. not a `CriterionGrader`, is assumed to add the NA option; always with the default `auto_na_option`, so under `improve_rubric`, whose `_run_held_out` builds a default `CriterionGrader`, `"as_category"` is unavailable for any rubric with an ordinal multi-choice criterion, its binary criteria included, since one `cannot_assess` drives both) or a label names one — because NA has no ordinal position for the weighted kappa (`filter_na_multi_choice` refuses `na_mode="as_category"` for the same reason) (`TestOrdinalAsCategory`). This is deliberately stricter than `compute_metrics`, which refuses only when the effective criterion it rebuilds has an NA option (NA observed, or declared by the author): refusing upfront keeps the loop from failing mid-run after spending calls. Regardless of mode, `coverage` and `ca_rate` are measured over the raw, pre-exclusion denominator — numerically aligned with `CoverageStats`.

**Serialization.** `_serialize_iteration` writes the new fields into `iter-{NN}.json`'s `held_out_diagnostics` block: `cannot_assess`, `mean_coverage`, `mean_ca_rate`, and per-criterion `kappa` / `coverage` / `ca_rate` / `confusion_matrix` (the matrix via `ConfusionMatrix.model_dump(mode="json")`, round-trippable with `ConfusionMatrix.model_validate`).

**Held-out HTML report.** `render_improvement_report_html` renders, for held-out iterations, a neutral handling-mode label (`CANNOT_ASSESS=<mode>`) plus mean coverage / CA-rate in the metrics bar, and a per-criterion table with Raw % Agreement (the judge-vs-ground-truth accuracy), Kappa, Coverage, CA-rate, Precision, FP-rate, FN-rate, and the 2x2 cells (TP/FP/TN/FN); for a multi-choice criterion Precision, the FP/FN rates and the 2x2 cells are binary only and show `n/a` (its matrix, labelled by option, is not a MET/UNMET 2x2; the kind is read from `false_positive_rate is None`, never from the matrix labels, so options labelled `MET`/`UNMET` get no 2x2 cells either). It carries **no statistical conflation/cluster note** — single-source discipline keeps those exclusively in `MetricsResult.summary()`.
