### Inter-judge Agreement (Krippendorff's α + Fleiss' κ)
`compute_metrics()` reports inter-judge agreement (judges vs. each other, independent of ground truth) for binary, ordinal, nominal criteria, populated only when the report is an **ensemble with ≥2 judges and ≥2 items** — else both stats are `None`. Per-vote errors (`JudgeVote.error` / `MultiChoiceJudgeVote.error`) are excluded so only genuine judgments count. The items are every non-errored ensemble item with ground truth, whether or not it has a score (*Errored items and score pairs* below).

**Krippendorff's α (`krippendorff_alpha`) is the general, recommended statistic** — handles unequal/missing raters and is **level-aware** (`level="ordinal"` for ordinal — distance-aware — vs `level="nominal"` for binary/nominal), fixing Fleiss's order-ignoring. `_compute_krippendorff_alpha()` builds a per-criterion **reliability matrix** (rows = judges in `judge_scores` order, columns = items; cell = judge's numeric code, or `np.nan` when errored/excluded/absent). Binary codes: MET=0, UNMET=1, CANNOT_ASSESS=2 (only under `as_category`; `exclude` → `np.nan`, `as_unmet` → UNMET). Multi-choice cell = `selected_index` (genuine NA included). A cascade decision model's `superseded` votes are **kept** as its ratings (α is the only place its agreement with the escalation judges on escalated criteria is measured; see *Cascade reports*). α uses ALL items (missing handled), no complete-case dropping. Guards `<2` units / `NaN` / exceptions → `None`.

**Fleiss' κ (`fleiss_kappa`) is the classic fixed-rater nominal measure, retained complete-case.** statsmodels requires uniform raters per subject, so `_build_fleiss_row()` includes a subject ONLY if its counted votes sum to exactly `n_judges` (items with any errored/excluded/CA-under-`exclude` vote drop from the Fleiss matrix but stay in α as missing cells). `superseded` votes are **not** counted, so a cascade never yields a complete row and its Fleiss κ is `None` (see *Cascade reports*). `_compute_fleiss_kappa` guards `NaN` → `None`. Binary categories follow `cannot_assess` (`exclude`/`as_unmet` → 2 columns, `as_category` → 3 incl. CANNOT_ASSESS); multi-choice uses one column per option, genuine NA as an ordinary column. Both `fleiss_kappa` and `krippendorff_alpha` are **ground-truth-independent** (inter-judge only), so they are computed for a criterion even with **zero GT-paired samples**: the binary/ordinal/nominal per-criterion empty-data branches all call `_compute_fleiss_kappa(fleiss_matrix)` and pass `krippendorff_alpha` through (only the pred-vs-truth metric *values* go `None` there) — aligned ordinal/nominal, which previously hardcoded `fleiss_kappa=None`.

`krippendorff` (numpy-only) and `statsmodels` are both **hard dependencies**; the import guards (`HAS_KRIPPENDORFF` / `HAS_STATSMODELS`) in `_compute.py` stay for safety.

Both stats appear in `MetricsResult.summary()` and `to_dataframe()` (`_types.py`). `to_dataframe()` always emits `krippendorff_alpha` / `fleiss_kappa` columns (`None`/`NaN` where N/A — aggregate/judge rows, single-judge criteria). `summary()` appends `Kripp-α` (recommended, leads) + `Fleiss` columns to a criterion-type table only when ≥1 criterion in that group has a non-`None` value (single-judge output unchanged); per-criterion `None` renders as `n/a`.

**Framework principle: prediction-vs-ground-truth categorical agreement is reported as Cohen's kappa across the board** — binary `CriterionMetrics.kappa` (unweighted, possibly 3-class under `cannot_assess="as_category"`), ordinal `OrdinalCriterionMetrics.weighted_kappa` (quadratic-weighted), nominal `NominalCriterionMetrics.kappa` (unweighted); the orthogonal abstain decision uses `NAStats.na_kappa` ({NA, not-NA}) and the binary parallel `CannotAssessStats.ca_kappa` ({CANNOT_ASSESS, not-CANNOT_ASSESS}). All are chance-corrected and Landis & Koch interpretable via `KappaResult.interpret_kappa`. **Distinct** from inter-judge agreement (above), which uses `krippendorff_alpha` + `fleiss_kappa`. New pred-vs-truth categorical agreement metrics should land kappa-shaped, not as ad-hoc proportion metrics.

### Aggregate / per-judge scalar metrics: None when undefined, and type-handling parity
**A metric is `None` when genuinely undefined / not-applicable, never a fake `0.0`** (see *Undefined → None*). Aggregate scalars `criterion_precision`/`recall`/`f1` are the **binary MET-vs-rest** metric → `None` for a multi-choice-only rubric (no MET class; multi-class P/R/F1 lives in each criterion's `per_option`). `criterion_accuracy` generalizes (binary label accuracy when ≥1 binary criterion exists, else multi-choice exact-match), `mean_kappa` is the mean of per-criterion kappas — both `None` only with no comparable pairs / no kappa contributed. Aggregate + per-judge paths share one helper **`_criterion_level_scalars(...)`** (`_compute.py`; binary label/MET flats, falls back to multi-choice exact-match with no binary criterion); `_mean_or_none(values)` is the None-safe mean. The constructor wraps each scalar `x if x is None else float(x)`.

**Per-judge metrics mirror the aggregate's type handling field-for-field.** `_compute_judge_metrics` collects binary `cr.votes` and multi-choice `cr.multi_choice_votes` (records each judge's `selected_index` per item, NA-normalized via the SAME `effective_criteria` as the aggregate, captures the matching vote's `error` so errored MC votes skip with binary parity). It builds each judge's per-criterion kappas by reusing the aggregate's exact construction — binary `cohen_kappa_score` on prepared label reps (appended only when label pairs exist), ordinal `_compute_ordinal_criterion_metrics(...).weighted_kappa`, nominal `_compute_nominal_criterion_metrics(...).kappa` (appended after `filter_na_multi_choice`) — then calls `_criterion_level_scalars`. **Invariant: a 1-judge "ensemble" yields `per_judge[only]` equal to the aggregate field-for-field** (accuracy, mean_kappa equal; P/R/F1 both-None-or-equal; **and `phi` equal** — see below). `JudgeMetrics` widened its five scalar fields to `float | None`.

Each judge also gets `phi` and a `confusion_matrix`. The per-judge `confusion_matrix` is a 3×3 `ConfusionMatrix` with labels `["MET", "UNMET", "CANNOT_ASSESS"]` (the abstain class last), built by `_build_binary_judge_confusion_matrix` from the judge's **RAW pre-`cannot_assess`-filter** binary verdicts **pooled across all binary criteria** (errored/type-mismatched cells already dropped, but CANNOT_ASSESS abstentions preserved as their own class so filtering cannot hide them). Because every judge uses the same fixed class order, the aggregate of per-judge matrices is their elementwise sum; it is `None` when the judge contributed no binary verdict pairs (no data → no matrix, never a fabricated all-zero matrix).

### Errored items and score pairs
Which items `compute_metrics` reads, and which of them enter the score-level metrics (#18; item-level story from grader to metrics: [Abstention Handling](abstention.md)).

- **Errored items (`_is_errored_item`).** An item has no usable judgment when its grading raised (`ItemResult.error`), its report is an error report (`report.error`: `EvalRunner._create_error_report`, the grader's "No judge results to aggregate", `"Every criterion's judgment failed: ..."`), or every criterion report of it failed (`_judgment_failed` on each: its `is_error`, or a legacy dict-shaped report's `"error"`, as the grader's `_every_judgment_failed` reads them). The last catches an item whose every criterion's judgment failed in a run saved before such reports carried an `error` (stored with a fabricated score, e.g. `0.0` under `SKIP` or the worst case for `unknown` failures, and no error) or from a grader that sets none, so metrics recomputed from old runs leave it out too. An errored item is skipped before anything is read from it: no verdicts, no score, no per-judge data, no inter-judge agreement. It is counted in `n_errored_items` (the raw coverage denominator; each of its pairs in `CoverageStats.n_errored` under the `exclude` modes) and named in the warning `"<n> item(s) with ground truth were excluded from metrics because grading errored; their verdicts and scores do not contribute."` (any mode). `n_items` counts only non-errored items with ground truth, so a run all of whose items are errored raises `ValueError("No valid items with ground truth found")` rather than return metrics built on fabricated scores (`test_no_metrics_when_every_items_every_judgment_failed`, `test_llm_grader_whose_every_call_failed_has_nothing_to_measure`). `_compute_per_item_pooled_metrics` skips errored items by the same check, counts them in its own `n_errored_items`, appends the same warning and raises the same `ValueError` when no item is left; it has no `CoverageStats` (`test_per_item_rubrics_leave_out_an_item_with_every_judgment_failed`). Pinned by `tests/metrics/test_all_errored_items.py` (four of its tests in both the current and the saved-before style, `STYLES`) and `test_an_error_report_is_an_errored_item` (`tests/metrics/test_compute_metrics.py`).
- **Failed cells (`per_criterion_failed`).** On an item that is not errored, a criterion whose judgment failed (`_judgment_failed`) is a failed cell: neither a prediction nor an abstention, in every `cannot_assess`/`na_mode` ([Abstention Handling](abstention.md)). The main loop appends to `per_criterion_failed` alongside `per_criterion_pred`/`per_criterion_true`, so the three stay item-aligned; after the NA normalization, `_judged_cells(per_criterion, per_criterion_failed, items=None)` gives `judged_pred`/`judged_true`, which every criterion-level consumer reads (per-criterion metrics, `_criterion_level_scalars`, coverage, `NAStats`, `CannotAssessStats`). `_compute_bootstrap_ci(per_criterion_pred, per_criterion_true, per_criterion_failed, ...)` still resamples whole items with one shared index and calls `_judged_cells(..., idx_v)` on each replicate, so its RNG draws, and the intervals of a run without failures, are unchanged. The `_needs_na` reconstruction check reads judged cells only, and its per-judge fallback skips a judge's failed votes (`judge_errors`), so neither adds the NA option: a panel judge's failed forced-choice vote no longer adds an all-zero NA row/column, nor makes `na_mode="as_category"` refuse an ordinal criterion. The coverage block adds each criterion's failed cells to its `n_errored`, and `_failed_judgments_warning(n)` appends `"<n> criterion judgment(s) on graded items failed and were left out of the criterion-level metrics."`. The pooled path skips a failed cell before pooling and counts it for the same warning. The aggregate thus agrees with the per-judge metrics, which skip errored votes (`tests/metrics/test_failed_criteria.py`). The item's score is the grader's, stand-ins included, so its score pair is unaffected.
- **Score pairs need both scores (per-criterion path).** Each non-errored item's true score is `dataset.compute_weighted_score(...)` of its ground truth under its effective rubric (`get_item_rubric`), `None` when the ground truth leaves nothing to score (every label abstains). The item enters `all_pred_scores`/`all_true_scores` only when both `report.score` and the true score are defined: an item with nothing left to score, or whose ground truth leaves nothing to score, keeps its verdicts in the criterion-level metrics but adds no pair to `score_rmse`/`score_mae`/the correlations/`bias`/`bootstrap.rmse_ci`, never a pair through a fabricated `0.0`. With no pair at all, `compute_metrics` refuses with a `ValueError` beginning "No valid items with a computed score found" and saying why (every graded item has nothing left to score, in its grade or its ground truth; `test_no_score_pairs_at_all_is_refused_with_its_cause`), so `MetricsResult`'s aggregate score fields stay non-optional. The pooled path's score fields pool rubric-point values instead of item scores (*Per-item heterogeneous rubrics: pooled rubric-point metrics* below), and it refuses in the same way when the graded items leave no rubric point to pool.
- **Per-judge data is collected apart from item scores.** Per-judge data and inter-judge agreement (Fleiss rows, α cells) come from every non-errored ensemble item, with a score or without; `judge_true_scores` holds each collected item's true score (`None` where undefined), aligned with the per-judge lists, and `_compute_judge_metrics(true_scores=judge_true_scores, ...)` pairs a judge's score with it where both are defined (`test_an_item_with_nothing_left_to_score_counts_for_each_judge`). A judge's score on an item is read as `None` when it cast votes there (`_criterion_votes`: binary `votes` and `multi_choice_votes`) and every one failed (`_judge_failed_every_vote(report, judge_id)`), whatever the saved `judge_scores` entry says (a run saved before those entries were `None`). The absent-judge check compares a judge's list with `len(judge_true_scores)`: `ValueError("per_judge=True needs every item graded by the same judges, but judge 'b' is in the judge_scores of 2 of 4 graded items (did the judge set change between items, e.g. on a resumed run?). Use per_judge=False for the other metrics.")` (the *Undefined judge score* bullet under *Undefined → None*).

### Cascade reports: missing votes, superseded votes, escalation-judge coverage
A confidence cascade's report: a criterion that was not escalated carries only the decision model's vote; an escalated one (`EnsembleCriterionReport.escalated=True`) carries the decision model's vote with `superseded=True` followed by the escalation judges' votes, which alone give the final verdict; `judge_scores` holds `None` for each escalation judge. Per-judge discovery keys off `report.judge_scores`, so escalation judges are discovered.

- **Missing votes are missing, not a verdict.** The per-judge rows `compute_metrics` builds (items × criteria) carry a parallel `judge_missing` mask, set at the two fill-in sites where a judge has no vote on a criterion: binary (the slot holds a placeholder `UNMET`, formerly counted as a prediction) and multi-choice (the slot holds a placeholder `None` in `judge_mc_preds`, which formerly read as a genuine error-abstain: it triggered NA-option reconstruction via `_needs_na` and was normalized to the NA index, i.e. counted as an NA prediction). The `UNMET` in the binary slot of every multi-choice criterion is a layout placeholder, not a fill-in (the mask is per cell). Masked cells are excluded from the `_needs_na` reconstruction check and the per-judge None→NA normalization, and `_compute_judge_metrics` skips them first: they count neither as predictions nor as abstentions. A `superseded` vote is present (the decision model's prediction), so the decision model is measured over every criterion.
- **Where the fill-in fired before.** Full panels (every item graded by the same judges, one vote per judge per criterion) never reach it, so their metric values, `summary()` texts and `to_dataframe()` frames are bit-identical to the pre-change library's on the same interpreter and platform: `tests/metrics/test_full_panel_metrics_golden.py` pins them against `tests/golden/metrics/full_panel_metrics.json`, captured from the pre-change library by `capture_metrics_fixtures.py` (hand-built panels, a single-judge run and a mock-graded panel under several settings; CPython 3.12 on macOS arm64). The test compares everything exactly except floats, which it compares up to `FLOAT_TOLERANCE` (1e-12, relative or absolute near zero) via `assert_same`: a float's last bits depend on where it is computed, whichever library computes it (the builtin `sum()` of floats is compensated only from Python 3.12, e.g. `mean_kappa` through `_mean_or_none`; numpy dot products behind the Pearson coefficient run through the platform's BLAS; libm reaches the p-values). A run mixing judge sets (e.g. resumed after swapping a judge) fabricated an NA option on multi-choice criteria even with `per_judge=False` (an extra `Cannot assess / not applicable` row/column in the confusion matrix and `per_option`); those cells are now masked. `per_judge=True` on such a run still raises the absent-judge `ValueError` (the *Undefined judge score* bullet under *Undefined → None*).
- **Escalation-judge coverage.** `JudgeMetrics.coverage: Literal["full", "escalated"] = "full"` and `n_pairs: int | None = None`, set in `_compute_judge_metrics` **by role**, which `compute_metrics` reads from the cascade's structure and passes as `escalation_judge`: over the non-errored ensemble items it collects the judges that vote on some criterion that was not escalated (`judges_voting_unescalated`) and those that cast a `superseded` vote (`judges_superseded`), reading each criterion's votes through `_criterion_votes`; a judge in neither set is a cascade escalation judge → `"escalated"`. Its criterion-level metrics cover exactly the cells it voted on (masked cells are skipped), i.e. the escalated subset; its score-level fields are `None` (its `judge_scores` entries are `None` by role); `n_pairs` counts the (item, criterion) cells that entered its criterion-level metrics — a genuine (present, error-free) vote paired with ground truth of the criterion's type — before the `cannot_assess` / `na_mode` handling (abstentions on either side included, then handled as for every judge). The rule does not depend on how many criteria escalated: an all-escalated run (e.g. the decision model failed on every item) is still an escalated subset, and an escalation judge consulted on nothing (no vote anywhere, so in neither set) gets `n_pairs=0` with `None` criterion metrics. Every other judge (LLM panel members, a cascade's decision model, mixed ensembles without escalation) is `"full"` with `n_pairs=None`. The role is not read off the scores, which since #18 are `None` for other reasons too: a panel judge whose every call failed on every item (all-`None` `judge_scores`) votes on unescalated criteria, so it stays `"full"`, with `None` score fields (`test_a_panel_judge_down_for_the_whole_run_is_not_an_escalation_judge` and `test_llm_judge_whose_every_call_failed_has_no_score_metrics` in `tests/metrics/test_all_errored_items.py`).
- **Output for full panels is unchanged; dumps gain two additive keys.** A full panel's metric values, `summary()` texts and `to_dataframe()` frames are as before. `coverage` / `n_pairs` are serialized like every other field (as are the additive report fields `probabilities` / `confidence` / `superseded` / `escalated`), so a full panel's `model_dump` / `model_dump_json` gains `"coverage": "full"` and `"n_pairs": null` in each `per_judge` entry and nothing else; dumps round-trip through `model_validate`, and a dump written before the fields existed validates to their defaults. The checks accept exactly these two keys at these values: the full-panel golden (`ADDED_JUDGE_METRICS_FIELDS` / `dumped_today` in `test_full_panel_metrics_golden.py`), the legacy-pickle test (`NEW_JUDGE_METRICS_FIELDS`) and the parity harness's `metrics.json` comparison for R4 and R7 (`KNOWN_NEW_METRICS_KEYS` in `scripts/parity/compare_parity.py`, reported as new keys at defaults, like R3's report keys). `summary()` appends ` (escalated subset, N pairs)` to an escalation judge's per-judge line; full judges' lines are unchanged. `to_dataframe()` adds `judge_coverage` / `n_pairs` columns (last; `None` outside the judge rows) only when some judge is `"escalated"`.
- **Inter-judge agreement.** Fleiss (`_build_fleiss_row`) skips `superseded` votes, so κ is `None` for a cascade (a cascade is not a panel). Krippendorff's α (`_build_alpha_cell`) keeps them; units of non-escalated criteria have one rating and are unpairable. Mixed ensembles without escalation are ordinary full panels for both statistics.
- **Pooled path.** `_compute_per_item_pooled_metrics` reads only final verdicts (`extract_all_verdicts_from_report`) and has no per-judge output, so superseded votes and missing cells cannot affect it; per-judge metrics for heterogeneous per-item rubrics are out of scope.
- **Cascade diagnostics.** No block is added to `MetricsResult`: `escalation_stats` (`escalation.py`) reads the `escalated`/`superseded` flags over pooled (item, criterion) pairs, so it also covers per-item heterogeneous rubrics, and returns an `EscalationPoint` (escalation rate; decision-model accuracy on the kept pairs and on the deferred ones — escalated for their confidence, a decision-model failure or abstention being no prediction — read as per-judge metrics read a judge; the fallback's accuracy, its final verdicts read as the aggregate reads them, on the same deferred pairs, so the two escalated accuracies compare the judges pair for pair; the run's metric from `compute_metrics`; it keeps the pairs of an item whose every criterion's judgment failed, which `compute_metrics` leaves out as errored, in `escalation_rate` only, since a failed judgment, the decision model's or the fallback's, is in neither accuracy, as it is in no metric); `calibrate_escalation` measures each replay of a threshold sweep the same way, into an `EscalationCurve` (on the pooled path its default `criterion_accuracy` is the exact accuracy over the points of every scale, a point whose prediction abstains left out and one whose label abstains a miss). Definitions, the zero-call `replay_escalation` and the calibration: [Offline Cascade Replay, Diagnostics and Calibration](grading-flow.md).

### Per-item heterogeneous rubrics: pooled rubric-point metrics
The per-criterion path indexes everything by one shared criteria list and **raises** if items' rubrics differ in criterion count. Datasets where each item carries its **own** rubric with genuinely different criteria (e.g. HealthBench) therefore have no shared per-criterion table. `compute_metrics(..., per_item_metrics=...)` (`"auto"` default; also `"pooled"`/`"per_criterion"`) dispatches to **`_compute_per_item_pooled_metrics`** when `dataset.rubric is None` **and** `_has_heterogeneous_rubrics(...)` is true (item rubric *signatures* — requirement + scale_type + option labels via `_rubric_signature` — differ). Each item is graded against `dataset.get_item_rubric(idx)`; every rubric point reduces to a normalized **value** in [0, 1] (binary MET=1/UNMET=0, multi-choice `option.value`) and an **exact-selection** match, pooled within its scale type, via the report-type-agnostic `extract_all_verdicts_from_report` + `resolve_ground_truth` + the same `with_guaranteed_na_option` effective-criterion reconstruction the per-criterion path uses (abstentions — `CANNOT_ASSESS`/NA — excluded; a failed cell is neither a point nor an abstention, *Errored items and score pairs* above). The result sets `per_criterion=[]` and fills **`MetricsResult.pooled_by_scale: list[PooledScaleMetrics]`** (one entry per scale present). `PooledScaleMetrics` carries `scale_type`/`n_points`/`exact_accuracy`/`value_rmse`/`value_mae`/`value_spearman`/`value_pearson`/`n_abstain`; the categorical block (`kappa`/`phi`/`precision`/`recall`/`f1`/`confusion_matrix`) is populated **only for `binary`** (MET/UNMET is a universal 2-class space) and is `None` for ordinal/nominal (weighted/nominal κ, per-option, and an N×N confusion are undefined across differing option sets — honoring *Undefined → None*). Aggregate scalars carry the overall exact-match accuracy + the unified value pool (`score_rmse`/`score_mae`/correlations/`bias`); `mean_kappa`/`criterion_phi`/`micro_kappa` mirror the binary pool (or `None`). When the graded items leave no rubric point to pool (no prediction could be paired with its ground truth, e.g. every one abstained), every pooled metric is undefined and `MetricsResult`'s score fields are non-optional, so the path raises `ValueError("No valid rubric points found: no prediction on the graded items could be paired with its ground truth, so the pooled metrics are undefined")` instead of reporting a fabricated `0.0` RMSE/MAE (`test_no_point_left_is_refused_with_its_cause` in `tests/metrics/test_per_item_pooled.py`); `escalation_stats` and `calibrate_escalation`, which compute metrics on such datasets, pass the error on. The homogeneous per-item case (no global rubric, identical signatures) stays on the per-criterion path — its weighted-score step now passes `dataset.get_item_rubric(idx)` so it no longer raises on the absent global rubric.

### Matthews correlation (φ) and macro/micro aggregates
`_mcc_or_none(met_true, met_pred)` is the single helper for the φ coefficient (Matthews correlation) on the binary MET-vs-rest dichotomy. It carries a **mandatory `len(set(...)) < 2 → None` guard on either side** because `matthews_corrcoef` silently returns a misleading `0.0` on constant/single-class input; a NaN result likewise maps to `None`. φ equals Cohen's κ on matched (balanced) marginals and exceeds it as the positive-rate marginals drift apart (e.g. the 2×2 `[[40,10],[20,30]]` gives κ≈0.400, φ≈0.408).

`_criterion_level_scalars` was widened from a 5-tuple to `(accuracy, precision, recall, f1, mean_kappa, phi, micro_kappa)`, computing **micro** φ (`_mcc_or_none` over the pooled binary MET flats) and **micro** Cohen's kappa (`_kappa_or_none` over the pooled binary label reps) from the SAME flats — so the aggregate `criterion_phi`, the per-judge `JudgeMetrics.phi`, and the bootstrap path all bind to one source and a 1-judge ensemble's φ equals the aggregate's by construction. Both are `None` for a multi-choice-only rubric (no MET class) and `None` on degenerate single-class pooled data. The aggregate also exposes `macro_accuracy` (unweighted mean of per-criterion `accuracy`/`exact_accuracy` via `_mean_or_none`), `micro_kappa` (the pooled value above, distinct from the macro `mean_kappa`), and `mean_krippendorff_alpha` (macro mean of the per-criterion α). Each binary `CriterionMetrics` carries a 2×2 `ConfusionMatrix` (labels `["MET","UNMET"]`) built by `_build_binary_2x2_confusion_matrix`, plus `fpr`/`fnr` taken from that matrix's undefined→None properties, per-criterion `phi`, and `is_degenerate` (True iff it had samples but `kappa is None`); ordinal/nominal set `is_degenerate` on `weighted_kappa is None` / `kappa is None`.

`compute_metrics` appends two diagnostic warnings: a **score-collapse** warning when the per-item ground-truth scores take ≤2 distinct values (rank correlations on a collapsed range are uninformative), and a **degeneracy** warning naming the criteria whose agreement coefficient collapsed to `None` despite having samples.

### Rendering: `summary()` / `to_dataframe()` and the single-source notes

`MetricsResult.summary(*, verbose=False)` and `to_dataframe()` (`_types.py`) are the **only** surfaces that render the conflation / cluster / geometry / φ-gap notes — these notes live here (and in the field docstrings), never in `meta/_display.py`. Both render through the module-level None-safe formatter **`_fmt_opt(value, spec, width=0)`**, which shows `None` as right-aligned `'n/a'`.

`summary()`:

- **Handling-modes line** — `Handling modes: CANNOT_ASSESS=<cannot_assess_mode>, NA=<na_mode>`, so every accuracy/kappa/F1 carries its estimand (a number reported without its handling mode is ambiguous among the three estimands).
- **Micro/macro labels** — the criterion-level block names each scalar's aggregation level: `Accuracy (micro)` / `Accuracy (macro)` / `Precision (micro)` / `Recall (micro)` / `F1 (micro)` / `Mean Kappa (macro)` / `Kappa (micro)` / `Phi (micro)` / `Mean Kripp-α (macro)`. Binary-only P/R/F1 and `Phi (micro)` render only when at least one binary criterion exists.
- **Score block** — header reads `Score-Level Metrics (continuous per-item weighted score):` to declare the scale (these are not binary-verdict correlations).
- **φ cluster + conflation note** — `Phi (micro)` sits in the κ cluster with the single-source note that on binary data φ = Pearson = Spearman = Kendall = MCC and the κ − φ gap is the judge's positive-rate drift (not extra evidence).
- **Type-aware inter-judge rendering** — for **binary/nominal** criterion groups Krippendorff's α is the single primary column and the **bare Fleiss column is dropped** (they coincide up to a finite-sample correction `(1 − κ_F)/(N·R)`); a single conflation note explains the omission (the note may name Fleiss, but no Fleiss data column is rendered). For **ordinal** groups both α (distance-aware) and Fleiss (nominal) are kept with a **different-geometry** note (a distinguishing note, not a conflation note).
- **Binary confusion cells + coverage continuation** — each binary row shows `Phi`, `FP`, `FN`, `FPR`, `FNR` (from `CriterionMetrics.confusion_matrix` / `.fpr` / `.fnr`); under the `exclude` mode an aggregate **Coverage** continuation line renders the `coverage_stats` (coverage %, judge/gt abstain rates, errored count).
- **Degenerate vs no-data** — a criterion with `is_degenerate=True` (samples present, agreement undefined) is suffixed with a distinct `[degenerate: ...]` marker, not silently shown as `n/a` like a no-data (`n_samples==0`) criterion.
- **Per-judge swap + `verbose`** — the default per-judge line leads with the chance-corrected `Acc` + `Mean Kappa` + `Phi` (was RMSE + Spearman). The keyword-only `verbose=True` flag adds the secondary numeric columns (RMSE, Spearman, MAE, through `_fmt_opt`) and prints each judge's confusion matrix; the default omits both. An escalation judge's line ends with ` (escalated subset, N pairs)` (see *Cascade reports*).

`to_dataframe()` aggregate-row keys are **level-labelled** — `accuracy_micro` / `precision_micro` / `recall_micro` / `f1_micro` / `kappa_micro` / `phi_micro` (pooled) and `accuracy_macro` / `mean_kappa_macro` (unweighted means), plus `mean_krippendorff_alpha`, the handling modes (`cannot_assess_mode` / `na_mode`), `n_samples`, and the coverage columns (`coverage` / `judge_abstain_rate` / `gt_abstain_rate` / `union_exclusion_rate` / `n_errored` / `error_rate`; `None` outside exclude mode). The former bare `accuracy` / `precision` / `recall` / `f1` / `kappa` columns are **removed** (they mixed levels). Per-criterion rows add `phi` / `fpr` / `fnr` / `is_degenerate` and the coverage columns; the bare `fleiss_kappa` value is emitted only for ordinal criteria (binary/nominal leave it `None` — α primary). Per-judge rows add `phi`. The store tolerates `None` (emits JSON null / NaN). The handling modes round-trip through `to_file` (they are frozen fields, serialized by `model_dump_json`).

### "Undefined → `None`, never a fabricated `0.0`" — the cross-cutting invariant
A single principle across grading → metrics → improvement loop: **a metric / statistic / score / coefficient is `None` when genuinely undefined (no data, degenerate input, computation failed, or not-applicable), never a stand-in `0.0`/`1.0`.** Counts (`n_samples`, `support_*`, confusion cells) stay `0`; aggregates average only defined values (`_mean_or_none`) and are `None` if none defined; renderers show `None` as `n/a` and never crash. Modeled on the pre-existing `na_kappa`/`ca_kappa`/`BiasResult.{p_value,effect_size,ci}` handling. Applies to:

- **Kappa (Cohen's, all paths).** `_kappa_or_none(y1, y2, *, weights=None)` (`_compute.py`) is the single helper for every pred-vs-truth Cohen's kappa (binary per-criterion, ordinal `weights="quadratic"`, nominal, per-judge, the `NAStats.na_kappa`/`CannotAssessStats.ca_kappa` dichotomies, `validate_held_out`). With fewer than two labels across both sides (single-class data: chance agreement is total, so kappa is 0/0) it returns `None` **without calling** `cohen_kappa_score`, which would warn twice (`"A single label was found ..."`, then `"invalid value encountered ..."`) about what `None` already says; this is the same mandatory guard `_mcc_or_none` has, and it reads both sides together, so constant sides with different labels give a defined `0.0`. Otherwise it returns `None` on exception **or a NaN result** (`cohen_kappa_score` returns NaN with no exception; the old `except: 0.0` let it leak). Pinned by `test_kappa_on_one_label_is_none_without_warnings`, `test_kappa_with_two_labels_across_constant_sides_is_defined` and the two `compute_metrics` tests `..._without_sklearn_warnings` (`tests/metrics/test_none_when_undefined.py`). `None` kappas are excluded from `mean_kappa` via `_mean_or_none`.
- **Empty-data criteria.** With zero usable paired samples, a criterion's metric values (`accuracy`/`precision`/`recall`/`f1`/`kappa`, ordinal `exact_accuracy`/`adjacent_accuracy`/`weighted_kappa`/`rmse`/`mae`, nominal `exact_accuracy`/`kappa`, `OptionMetrics.precision/recall/f1`) are `None`; only counts stay `0`. `_compute_adjacent_accuracy([])` returns `None`.
- **Correlations.** `_compute_correlation` returns `CorrelationResult.coefficient = None` (and `p_value = None`) for `<3` samples (`interpretation="insufficient data"`) or a constant array (NaN → `interpretation="undefined"`); `_interpret_correlation` is only called with a real float. `validate_ground_truth`'s Spearman likewise yields `None` on a constant rubric-score array. Since the constant-array case is handled, scipy's spurious `ConstantInputWarning`/`NearConstantInputWarning` is suppressed locally around the `spearmanr`/`kendalltau`/`pearsonr` calls.
- **Distribution (`distribution.py`).** `score_distribution` returns `None` for stats undefined at the sample size (`std`/`variance` at n<2, `skewness` at n<3, `kurtosis` at n<4, all central-tendency at n=0); a single point keeps its computable `mean/min/max/median/iqr`. `earth_movers_distance` on empty input returns `None` fields.
- **Bias (`distribution.py`).** `systematic_bias` computes `mean_bias` at n=1 (the single difference) with `std_bias=None`; at n=0 both `None`; `effect_size` is `None` when `std_bias == 0` (Cohen's d undefined). `BiasResult.{mean_bias,std_bias}` are `float | None`.
- **Inter-judge agreement.** `validate_agreement` returns `None` (not `0.0`) when no usable sample was measured; the empty-rubric grader path sets `EnsembleEvaluationReport.mean_agreement = None` (`float | None`, default `None`); improvement-loop consumers (`pareto_accept`, `_check_convergence`, best-tracking, formatting) treat `None` as "not measured".
- **Bootstrap (item-level, all rubric types).** `_compute_bootstrap_ci` resamples **items** (one shared index applied across all criteria; each replicate then drops each criterion's resampled failed cells, *Errored items and score pairs* above), recomputing the SAME reported aggregates per replicate via the shared `_per_criterion_kappas` + `_criterion_level_scalars` helpers (also used by `_compute_judge_metrics`), so `accuracy_ci`←`criterion_accuracy`, `kappa_ci`←`mean_kappa` (ordinal contributes quadratic-weighted kappa), `rmse_ci`←`score_rmse` — for binary, multi-choice, AND mixed rubrics (was binary-only: gated behind flattened binary labels, so pure multi-choice silently returned `bootstrap=None` and even lost `rmse_ci`). `_per_criterion_kappas` is the single source of truth for the per-criterion kappa list (binary Cohen on label reps appended only when label pairs survive; ordinal/nominal via `_kappa_or_none(..., weights=...)` on `filter_na_multi_choice`-filtered indices — the same primitive the metric functions use, so values match the aggregate without building throwaway metric objects per resample). **Two independent resample axes** (verdict-item for accuracy/kappa, scored-item — an item with a score pair, both scores defined — for rmse) → marginal CIs. `effective_criteria` is fixed once on the full sample (re-deriving per resample would jitter the NA index space / ordinal weight matrix). `BootstrapResults.{accuracy_ci,kappa_ci,rmse_ci}` are `tuple[float, float] | None` — `None` when the axis is empty or every replicate is degenerate (single-class → per-criterion kappa `None` → empty `kappa_samples`); a single scored item gives a degenerate `(v, v)` rmse CI (RMSE is defined n≥1). `summary()` skips a `None` CI line (bootstrap is not in `to_dataframe()`). The old binary path used **pair-flattening** (treats criteria within an item as independent → anti-conservative); item-level CIs are wider/correct, and the kappa CI now brackets the reported `mean_kappa` (the old per-binary pooled Cohen value bracketed no reported statistic). Single-class resamples raise no warnings, since `_kappa_or_none` never calls sklearn on them, so the loop needs no local warning filter.
- **No score: a failed grade, or nothing left to score.** `EvaluationReport.score`/`raw_score` and `EnsembleEvaluationReport.score`/`raw_score`/`llm_raw_score` are `float | None`, `raw_score` `None` exactly when `score` is. `None` means the item has no score: a failed grade (`error` set) — the explicit failure constructors (`EvalRunner._create_error_report`, the grader's "No judge results to aggregate" report) and the `"Every criterion's judgment failed: ..."` report of an item whose every criterion's judgment failed — or no criterion left to score (`score_reports` returns `None`; `error` `None`) ([Score Calculation](grading-flow.md)). Never a fabricated `0.0`, which is indistinguishable from a real catastrophic score. The scoring core never reads `report.score`. Consumers filter `error is not None` and are `None`-guarded: `EvalResult.get_scores()` filters `score is not None`; the length-penalty path (`graders/base.py`) returns a score-less report unchanged; `compute_metrics` leaves errored items out entirely and pairs scores only where both are defined (*Errored items and score pairs* above), with no `0.0` substitution; `meta/_display` renders `None` as `n/a`; `validate_ground_truth` raises `RuntimeError` on a failed grade (report `error` set) and leaves out an item with no score to compare, and the improvement loop raises `RuntimeError` when its meta-rubric quality evaluation has no score ([Improvement Loop Artifacts](improvement-loop.md)). Serialization round-trips `None` cleanly (writers coercion-free; readers index/`.get` without `float()`/`0.0` defaults).
- **Undefined judge score (per-judge score metrics).** `EnsembleEvaluationReport.judge_scores` values are `float | None`; `None` means the judge's whole-rubric score is undefined: **by role** — a judge consulted only on some criteria (e.g. an escalation judge) is `None` on every item, even one where it happened to judge every criterion — or on an item where every vote of the judge failed (it judged nothing, e.g. a decision model whose one request on an item of a mixed ensemble failed; `CriterionGrader.aggregate`, [Score Calculation](grading-flow.md)) or none of its verdicts is left to score. `compute_metrics` collects them item-aligned (`dict[str, list[float | None]]`, aligned with `judge_true_scores`), reading as `None` also a saved number of a judge every vote of which on the item failed (`_judge_failed_every_vote`: a run saved before #18 kept the score of that judge's error-abstentions, `0.0` under `SKIP`, or of its worst cases, for either judge kind). So a judge's score fields can be `None` on an LLM-only panel too (a judge whose every call failed on every item), and code formatting them must check `None` first, as the `autorubric.metrics` package docstring's per-judge example does (`rmse = "n/a" if jm.score_rmse is None else f"{jm.score_rmse:.4f}"`); the judge's errored votes are left out of its criterion-level metrics as before. Score-level metrics are undefined for a judge with no score to compare, so when no item pairs a defined judge score with a defined true score `_compute_judge_metrics` sets **every** score field of `JudgeMetrics` to `None`: `score_rmse`, `score_mae`, `score_spearman`, `score_kendall`, `score_pearson` (`CorrelationResult | None`) and `bias` (`BiasResult | None`). Otherwise they are computed over the items where both are defined (pairwise-complete, zipped `strict=True` with the true scores): a `None` on only some items is left out of the pairs, as the aggregate leaves out score-less items, never filled in. A judge *absent* from some items' `judge_scores` — a judge set that changed between items, e.g. a resumed run after swapping a judge — has no entry there, not a `None` entry, so its scores cannot be item-aligned: `compute_metrics(per_judge=True)` raises a `ValueError` naming the judge and on how many of the graded (non-errored ensemble) items it appears (message under *Errored items and score pairs* above; checked before `_compute_judge_metrics`; previously the length mismatch surfaced as an unexplained `ValueError`), while `per_judge=False` computes the other metrics as before. Criterion-level per-judge metrics come from the votes and are unaffected. A judge whose score is defined on every item always gets non-`None` score fields: a run with no score pair at all is refused before any judge is measured, and any item that has one is also in `judge_true_scores` with a defined true score. `summary(verbose=True)` renders the per-judge `RMSE`/`Spearman`/`MAE` through `_fmt_opt` (`n/a` for `None`), and `to_dataframe()`'s judge rows carry `None` for `rmse`/`mae`/`spearman`/`kendall`/`pearson`/`bias`; both read an optional correlation's coefficient via the `_coefficient` helper in `metrics/_types.py`.
- **Extraction failure.** `extract_all_verdicts_from_report` returns `None` for any criterion whose verdict can't be extracted — including the whole-report `report.report is None` branch (reachable by a direct call, or from a report with no criterion reports and no `error`; `compute_metrics` skips the grader's score-less "No judge results to aggregate" report as an errored item before extracting anything) — for BOTH binary and multi-choice, never a fabricated multi-choice option `0`. The consumer then maps binary `None` → `UNMET` (conservative default) and multi-choice `None` → the effective NA index, so a failed extraction is an abstain rather than a spurious option-0 vote that would corrupt per-criterion kappa / per-option support / NAStats / na_kappa.
