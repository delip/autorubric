# AutoRubric Development Reference

A Python library for evaluating text outputs against weighted criteria using AI judges such as LLMs and decision models.

**For detailed documentation, examples, and usage guides, see docs/.**

This reference is split into focused pages for gradual disclosure — load only the page you need. Start here for the package map, then follow the [Reference Map](#reference-map) below.

## Package Structure

```
src/autorubric/
├── __init__.py             # Public exports
├── content.py              # Image, Content: submission text, images and documents; digest helpers
├── data/
│   └── decision_models.json # Decision-model capability registry (images, image envelope), read by decision_model_capabilities
├── dataset.py              # DataItem, RubricDataset
├── decision.py             # DecisionModelConfig, DecisionModelClient (optional typesafe-sdk), capability registry lookup, framing + answer mapping
├── escalation.py           # replay_escalation, escalation_stats, calibrate_escalation, EscalationPoint, EscalationCurve (offline cascade tools)
├── eval.py                 # EvalRunner, EvalResult, evaluate()
├── llm.py                  # LLMConfig, LLMClient, ThinkingConfig, classify_grading_error
├── prompts.py              # Centralized prompt definitions (per-criterion and whole-rubric one-call prompts)
├── rate_limit.py           # RateLimitPool: per-provider, per-event-loop rate limiting
├── rubric.py               # Core Rubric class (criteria + optional guidelines), rubric file formats
├── scoring.py              # score_reports() shared weighted-scoring core
├── types.py                # Criterion, LengthPenalty, ensemble types, LLMCalls, RubricJudgment, etc.
├── utils.py                # JSON parsing, length penalty utilities
├── graders/
│   ├── __init__.py         # Grader exports
│   ├── base.py             # Abstract Grader base class
│   └── criterion_grader.py # Unified grader (single/ensemble/few-shot/cascade; LLM calls per criterion or per item), EscalationConfig
├── meta/
│   ├── __init__.py         # Meta-rubric evaluation exports
│   ├── _evaluate.py        # evaluate_rubric_standalone, evaluate_rubric_in_context
│   ├── _improve.py         # ImprovementRunner, improve_rubric, building blocks
│   ├── _display.py         # Rich display utilities
│   └── data/               # Meta-rubric JSON files
└── metrics/
    ├── __init__.py         # compute_metrics, result types
    ├── _compute.py         # Main compute_metrics implementation
    ├── _types.py           # MetricsResult, CriterionMetrics, etc.
    ├── _helpers.py         # Verdict extraction helpers
    └── distribution.py     # EMD, KS test, bias metrics
```

### Grading Flow & Score Calculation

The end-to-end grading pipeline: `Rubric.grade()` delegates to `CriterionGrader` (a single judge, `judge_model_config=`, is an "ensemble of 1"), which at `judge()` start normalizes the rubric **once** into an *effective rubric* (`_effective_criterion`) — with `auto_na_option=True` (default) every multi-choice criterion is guaranteed an NA abstain option via `Criterion.with_guaranteed_na_option()`, a pure same-length/order transform that keeps `criterion_idx` and the shuffle RNG key aligned and never mutates the user rubric; `auto_na_option=False` gives forced-choice. Images: `Grader.grade` loads the submission, query and reference submission once per grade before any judge is called (`_load_content_async`, `asyncio.to_thread` only when a file must be read; text untouched), a missing/unreadable/unsupported image raising from the grade (never routed), the `{thinking, output}` dict text-only (`_thinking_output_text`, `TypeError`); `CriterionGrader.judge` reloads idempotently, so every LLM judge (per-criterion calls, the `per_item` call, panel members, a cascade's escalation judges) sends the same loaded document as content parts; few-shot training submissions loaded once at construction (`_example_submission`, `_loaded_example_submissions`); an LLM judge is sent images only when known to accept them (`_check_judges_accept_images` before the gather, for `_judges` and `_escalation_judges`; `_check_llm_accepts_images`/`_llm_accepts_images`: `LLMConfig.images` when a `bool`, else `_litellm_supports_vision` (reads the loaded `litellm.model_cost` only, never `litellm.supports_vision`, so no request (Ollama's `/api/show` included); keys by `_map_keys` (provider-prefixed and bare, `responses/` route dropped, case-insensitive), entries for the model's provider by `_same_provider`/`_ANY_PROVIDER`; map fetched at import unless `LITELLM_LOCAL_MODEL_COST_MAP=True`), cached per grader by model in `_litellm_image_support`; refusal `_llm_image_refusal` → configuration `ValueError` naming judge and model, no request by any judge; training images checked at construction by `_check_examples_reach_judges_accepting_images`; text never asks; `tests/graders/test_llm_image_capabilities.py`); a decision-model judge writes each image's `<image:{sha256}>` reference into its state (`_state_text`, `_asset_reference`) and sends the images as System One assets (`state_images`, `DecisionModelClient.prepare_assets` in `asyncio.to_thread` before the request's `try`, only for content holding images, the registry (or the judge's `DecisionModelConfig.capabilities`, which replaces it, via `_judge_capabilities`) checked in `judge` before the judges' gather by `_check_judges_accept_images`/`_image_capabilities` (unlisted model without `capabilities` (the message suggests `DecisionModelConfig(capabilities=...)`) or `images: false` → configuration `ValueError` naming judge and model, no request by any judge, mixed panels included; the old-SDK image `ImportError` (`_sdk_image_type`) checked there too, so a mixed panel sends nothing; a malformed registry file a marked configuration error; `fill_ground_truth` re-raises all three via `_CONFIGURATION_ERROR_NOTE`), fitted images over `max_request_bytes` → `ValueError` before the request; fitting by `_fit_for_system_one`/`_system_one_size` into the model's registry entry (`decision_model_capabilities`): pass-through, frame 0, `exif_transpose`, 16-bit/`F` samples to 8 bits, Lanczos resize (none for a one-pixel change), white padding, PNG for palette/1-bit/alpha, PNG/JPEG via `typesafe_sdk.Image.from_pil`; fitting `ValueError`/old-SDK `ImportError` raise, never route; `TypeSafe-Danger-Zone-Images` header); the length penalty counts text only (`normalize_to_grade_input`/`compute_length_penalty` via `_content_text`, a newline per image); memory: each item in flight holds its images, an LLM judge's base64 data URLs and a decision model's fitted assets until its grade finishes, rate-limit waits included, so memory scales with `EvalConfig.max_concurrent_items` (unbounded by default; ### Multi-Choice Criteria

Multi-choice criteria end to end: `scale_type` `ordinal` (weighted kappa) vs `nominal` (unweighted kappa), explicit per-option `value` (0–1) and `shuffle_options=True` to mitigate position bias (LLM judges), option labels naming one option each (`_normalized_label`: the `Criterion` validator `validate_options` refuses repeated labels and, in a criterion without an NA option, a scored option labelled as `CANONICAL_NA_OPTION` (`_check_canonical_na_label`, also run by `with_guaranteed_na_option` for unvalidated criteria), both `ValueError`), and NA options (`na: true`) as the structural analog of binary `CANNOT_ASSESS` flowing through `score_reports` under the configured `CannotAssessStrategy`. Covers the first-class abstain channel: the auto-injected `CANONICAL_NA_OPTION`, NA-label rendering via `_render_options`/`_label_signals_na` in `prompts.py`, and the unconditional `MULTI_CHOICE_SYSTEM_PROMPT` NA section. Details scale-aware, option-driven empty/refusal handling — failure/lowest-quality option when one describes an empty submission (ordinal, scored ≈0) → else NA (nominal, SKIP-excluded) → else closest forced-choice option — and the same option-shape rule for contradictory/ambiguous submissions (the judge never sees weights, so scoring applies the weight sign downstream via option `value`). Specifies the three orthogonal ensemble aggregation knobs (`aggregation`, `ordinal_aggregation`, `nominal_aggregation`) on a central/conservative/permissive axis with the full value table, including nominal `unanimous` abstaining via the genuine NA option, and the multi-choice-only per-criterion override `Criterion.aggregation` (ignored for binary criteria). ### Metrics

The metrics layer: inter-judge agreement — Krippendorff's α (`krippendorff_alpha`, level-aware ordinal/nominal, built from a per-criterion reliability matrix tolerating missing/errored cells) and complete-case Fleiss' κ (`fleiss_kappa` via `statsmodels`, uniform-rater subjects) — both ground-truth-independent and computed even with zero GT-paired samples. States the framework principle that prediction-vs-ground-truth categorical agreement is always Cohen's kappa (binary `CriterionMetrics.kappa`, ordinal `weighted_kappa` quadratic, nominal `kappa`), with orthogonal abstain agreement via `NAStats.na_kappa` and `CannotAssessStats.ca_kappa`. Details aggregate/per-judge scalar parity: `criterion_precision`/`recall`/`f1` are binary MET-vs-rest (`None` for multi-choice-only rubrics), `criterion_accuracy`/`mean_kappa` generalize, sharing `_criterion_level_scalars` (now a 7-tuple also yielding `phi`+`micro_kappa`) + `_mean_or_none`; per-judge metrics mirror the aggregate field-for-field (1-judge == aggregate invariant, incl. `phi`). Covers the Matthews correlation φ helper `_mcc_or_none` (mandatory `len(set(...)) < 2 → None` guard against sklearn's misleading 0.0; φ≡κ on matched marginals, φ>κ on positive-rate drift), the binary 2×2 `ConfusionMatrix` + `fpr`/`fnr`/`phi`/`is_degenerate` via `_build_binary_2x2_confusion_matrix`, the per-judge 3×3 `["MET","UNMET","CANNOT_ASSESS"]` `ConfusionMatrix` via `_build_binary_judge_confusion_matrix` (RAW pre-filter codes pooled across binary criteria; aggregate == elementwise sum), the aggregate `criterion_phi`/`macro_accuracy`/`micro_kappa`/`mean_krippendorff_alpha`, `is_degenerate` on ordinal/nominal (`weighted_kappa`/`kappa is None`), and the score-collapse + degeneracy warnings. Which items count: errored items (`_is_errored_item`: `ItemResult.error`, a report `error` such as `"Every criterion's judgment failed: ..."`, or every criterion failed via `_judgment_failed`, so runs saved before #18 too; left out of every metric, each pair counted in `n_errored`, warned about, `ValueError` "No valid items with ground truth found" when all are errored, on the pooled path too), failed cells (a failed criterion of a non-errored item: `per_criterion_failed`/`_judged_cells`, out of every criterion-level metric, `NAStats`/`CannotAssessStats`, the bootstrap and the pooled path, never adding the NA option, errored pairs in `CoverageStats.n_errored`, `_failed_judgments_warning`; the aggregate of a one-judge ensemble equals its per-judge metrics), score pairs needing both the item score and the true score (either `None` → no pair, verdicts still count; `ValueError` "No valid items with a computed score found: ..." saying why), and per-judge data and inter-judge agreement over every non-errored ensemble item, scored or not (`judge_true_scores`). Exhaustively specifies the cross-cutting **"undefined → `None`, never a fabricated `0.0`"** invariant across Cohen kappa (`_kappa_or_none`: the one-label guard that keeps sklearn's single-label/NaN warnings out, plus NaN handling), empty-data criteria, correlations (`_compute_correlation`, <3 samples / constant arrays), distribution stats, systematic bias / Cohen's d, inter-judge agreement (`validate_agreement`, `mean_agreement`), item-level bootstrap CIs for all rubric types (`_compute_bootstrap_ci`, `accuracy_ci`/`kappa_ci`/`rmse_ci`), `None` report scores (a failed grade, or nothing left to score), `None` `judge_scores` entries (`_compute_judge_metrics` score fields `score_rmse`/`score_mae`/`score_spearman`/`score_kendall`/`score_pearson`/`bias`, `_coefficient`, `_fmt_opt`, a judge whose every vote on an item failed read as `None` there via `_judge_failed_every_vote`, changed-judge-set `ValueError` "per_judge=True needs every item graded by the same judges"), and extraction-failure `None` mapping. Cascade reports: the per-judge missing-vote mask `judge_missing` (a missing binary vote is not `UNMET`, a missing multi-choice vote is not an NA prediction and never triggers `_needs_na` NA-option reconstruction; also fixes mixed judge sets on resumed runs), `superseded` votes as the decision model's predictions, escalation-judge (votes on escalated criteria only, also under `llm_calls="per_item"`) `JudgeMetrics.coverage` (`"full"`/`"escalated"`, by role read from the votes — `escalation_judge` via `_criterion_votes`, `judges_voting_unescalated`/`judges_superseded`: no vote on an unescalated criterion, no `superseded` vote — not from all-`None` scores, so a panel judge down for the whole run stays `"full"`) + `n_pairs` (escalated-subset size) with score-level fields `None`, the `summary()` suffix `(escalated subset, N pairs)`, cascade-only `to_dataframe()` columns `judge_coverage`/`n_pairs`, `coverage`/`n_pairs` always dumped (a full panel's dump gains them at `"full"`/`null`; `ADDED_JUDGE_METRICS_FIELDS`/`dumped_today`, `NEW_JUDGE_METRICS_FIELDS`, parity R4/R7 `KNOWN_NEW_METRICS_KEYS`), Fleiss (`_build_fleiss_row`) skipping `superseded` votes (κ `None` for a cascade) while Krippendorff α (`_build_alpha_cell`) keeps them, cascade diagnostics in `escalation_stats` (pooled pairs, an `EscalationPoint`, no `MetricsResult` block) and `calibrate_escalation` (each sweep replay measured by `compute_metrics` into an `EscalationCurve`), and the full-panel bit-identity golden (`tests/golden/metrics/full_panel_metrics.json`, `capture_metrics_fixtures.py`; floats compared up to `FLOAT_TOLERANCE` via `assert_same` across interpreters and platforms). ### Reproducibility & Seed Coordination

How all non-LLM randomness is made deterministic. `CriterionGrader(seed=...)` controls option shuffling and few-shot selection; when `None` the `master_seed` is auto-generated so shuffles are always pinned; a given seed is read by `_as_int` (any integer, numpy too, stored as a plain `int` so the manifest records it; `bool`/float → `ValueError`, `tests/graders/test_grader_seed.py`). Per-call shuffle RNGs derive from `(master_seed, content_hash, criterion_idx, judge_id)` via SHA-256 (concurrency-safe, no shared mutable state) using `_derive_shuffle_rng()` in `criterion_grader.py` (content hash: first 16 hex digits of `_content_digest(submission)`, the submission's SHA-256 for text, the framed digest from `content.py` for a document; both `llm_calls` modes present a criterion through `_presented_criterion`, so its permutation never depends on how the judge is called); an unset `FewShotConfig.seed` is coordinated from the master seed, and few-shot selection RNGs derive from `(few_shot_seed, criterion_idx, judge_id)` with a constant `FEW_SHOT_DOMAIN` in the item-key slot (per criterion); under `llm_calls="per_item"` each judge draws whole training items once into `_item_examples` via `_select_item_examples`, keyed `(few_shot_seed, FEW_SHOT_DOMAIN, -1, judge_id)` (`-1` the whole-rubric criterion slot), greedy-coverage ties broken by that order, each item taken at construction as `(submission, labels, reasons)` (`balance_verdicts`, `n_examples`); an example's reason (`DataItem.ground_truth_reasons`) draws no randomness, so the same seed draws the same examples with or without reasons. `CriterionReport.shuffle_order` records the per-criterion permutation, and `ExperimentManifest.grader_config` persists `master_seed`/`shuffle_options`/`auto_na_option`, `llm_calls` only under `"per_item"` (right after `auto_na_option`, read from `_llm_calls` with `getattr`; per-criterion manifests byte-identical; `TestManifest`), plus `ExperimentManifest.images` (last field; `"images": true` written only for a dataset holding images, set by `_dataset_has_images` with `_has_images`, no I/O; text-only manifests byte-identical, `from_dict` `.get`, `TestManifestImages`), per-judge `judge_kind`, `temperature` (`null` = provider default), the LLM judge's optional `max_tokens`/`top_p`/`thinking` (`{"level", "budget_tokens"}` via `_thinking_entry`)/`seed`/`images`, each only when set (#44; byte-identical otherwise), and decision-model `binary_framing`/`ordinal_framing`/`decision_threshold`/`api_base_host` (the host resolved from `api_base`/`TYPESAFE_BASE_URL`; never the key, URL path or `extra_headers`; the base URL is no secret: failed reports' `error` shows it) (`_decision_model_judge_entry`) via `_serialize_grader_config` in `eval.py`, a cascade's `escalation` key (escalation judges via `_llm_judge_entry`, `threshold`, `per_criterion`, read from the grader's own copy `grader._escalation`), and the known `grader._normalize` gap. Cascade escalation judges keep each criterion's original `criterion_idx`, so their prompts match a non-cascade grader with the same `seed` and `judge_id` (`"escalation"` for a bare `LLMConfig`); under `llm_calls="per_item"` they make the full-rubric call `_judge_rubric_in_one_call` a non-cascade `per_item` grader makes (same `_item_examples`, shared response-cache entries under the `judge_id` `cache_namespace`), so a matching LLM run needs the cascade's `llm_calls`, as does `replay_escalation(..., llm_calls=)`. Response cache under `per_item`: one entry per (item, judge), the `LLMClient._cache_key` naming `RubricJudgment`, never colliding with per-criterion entries (`CriterionJudgment`/`MultiChoiceJudgment`), the parsed reply pickled with `_unusable` (`TestEndToEnd`); resume does not check `llm_calls` (mixes modes silently). With `auto_na_option=True`, a criterion that lacked an NA option gains one appended at the end, so its `shuffle_order` grows by one. `DecisionModelConfig` non-determinism and `cache_enabled`; images sent to a decision model are named by their original SHA-256 (`_asset_reference`) in the state and the cache key, which also holds the envelope's image limits (registry or `DecisionModelConfig.capabilities`, so changed limits re-ask; text keys unchanged), and fitted (`_fit_for_system_one`) deterministically for a given Pillow version; a decision-model manifest entry gets `capabilities` only when set (no `ImageCms` colour conversion). Image datasets: `ExperimentManifest.images` set by `_start_fresh_checkpoint`, informational only (resume relies on `_compute_dataset_hash`, which covers a document's images, including in `reference_submission`; `EvalResult.from_experiment`, `eval_config`, `to_dict` and `cache_dir` unchanged); `TestTheShuffleKey` pins the text shuffle key.

## How to update autorubric's dev reference

This reference uses **gradual disclosure**: `CLAUDE.md` `@`-imports only this `index.md`, so it loads every session as a lightweight router, while the eight detail pages load on demand when a link is followed. Preserve that property.

**Edit the page the change touches.** `types.md` for type/field changes, `grading-flow.md` for the grading pipeline or scoring core, `metrics.md` for metric computation, and so on. 

**Keep this index a router, not a copy.**

- Don't hyperlink the headings; give each page a **File location** line with its repo-relative path in backticks (e.g. `dev-reference/types.md`). Never use `@`-imports — an `@`-import would auto-load every page and defeat gradual disclosure.
- When you add, rename, or remove a page, update the **Reference Map** above with a keyword-dense TLDR, a **Load when** line, and a **File location** line. The TLDR is what makes a page discoverable, so name its key types, functions, config knobs, enum values, T-codes, and topics.
- When you add a new type, function, config knob, or T-code to a page, make sure the term also appears in that page's TLDR here — otherwise a reader scanning the index won't find it.
- Don't let the index grow toward monolith size: TLDRs + keywords route; the prose stays on the pages.

**Page conventions (so edits stay consistent).**

- Each page begins with the breadcrumb `[← Dev Reference Index](index.md)` and a blank line, then its content.
- A reference to another page's section becomes a cross-file link — `[Section Name](other-page.md)`. A reference to a section on the *same* page stays as italic emphasis (`*Section Name*`).
- **Dedup, don't drop facts.** The same mechanism is often restated in a type-table cell, an architecture page, and `conventions.md`. When trimming, consolidate to one canonical page and cross-link from the others — never delete a fact. Preserve verbatim every type/field/method/function name, enum value, table row, and code block.
