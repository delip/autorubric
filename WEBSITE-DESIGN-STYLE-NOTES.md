# WEBSITE-DESIGN-STYLE-NOTES.md

The canonical design guidepost for **autorubric.org**. Read this before adding or changing anything on the site so new work stays on-brand and never drifts from the established look and feel.

---

## 1. Purpose & scope

This document governs the **public landing page only**: the single self-contained file at `docs/landing/index.html` (564 lines; all CSS in one `<style>` block, lines 14–316; one line of JS for the footer year).

**Out of scope:** the MkDocs documentation site (`/docs/`), the cookbook (`/docs/cookbook/`), and the quickstart (`/docs/quickstart/`). Those are rendered by MkDocs Material (`mkdocs.yml`), have their own theming (`docs/assets/stylesheets/extra.css`), and are **not** governed here. The landing page links *to* them but does not share their CSS.

The page is a **single hand-authored HTML file with no CSS/JS framework** — no Tailwind/Bootstrap, no bundler, no build step *for the page itself*. Keep it that way: any contribution should remain a hand-authored, self-contained file. The "hero image" is live styled text (the code block), not a screenshot — there is **zero raster imagery** on the page (no `<img>`, no `url()`, no `background-image`, no favicon, no OG image).

### 1.1 Deployment & source of truth

Deployment is GitHub Pages via `.github/workflows/docs.yml`:

1. `mkdocs build --site-dir site/docs` builds the docs into `site/docs/` (served at `autorubric.org/docs/`).
2. `cp docs/landing/index.html site/` copies the landing page **verbatim** to the Pages root → served at `autorubric.org/`. MkDocs never touches it; it ships exactly as authored.
3. `cp docs/CNAME site/` carries the custom domain.
4. `actions/deploy-pages` publishes `site/`.

**The single source of truth is `docs/landing/index.html`.** The `site/` directory is **gitignored build output** (regenerated by CI / local `mkdocs build`) — never edit `site/…` by hand; your change will be overwritten. Because the landing page is `cp`'d (not templated), the absolute links in it (`/`, `/docs/`, `/docs/cookbook/`, `/docs/quickstart/`) resolve against the deployed root, not the local file path.

## 2. Design principles

Six principles, each derived directly from the page as built:

1. **GitHub-native dark.** The palette, the syntax colors, and the hairline-border section dividers are lifted from GitHub's dark (Primer) theme. New surfaces must read as part of that family — dark blue-gray backgrounds, `1px` `#30363d` borders, no drop shadows, no gradients.

2. **One gold accent, used sparingly.** `#f0b429` is the *only* chromatic accent. It is reserved for emphasis (the hero's second headline line), the single primary CTA, the feature-category eyebrows, and feature-icon strokes. It is never used for body copy or large fills. A one-accent system is the brand identity — do not introduce a competing hue.

3. **Scientific credibility over marketing hype.** Copy names specific biases, cites measurement theory, uses exact metric names (Cohen's kappa, EMD, KS tests), and carries a federal-funding (DARPA SciFy) disclaimer. There are zero superlatives. Restraint *is* the brand voice.

4. **Restrained, near-static motion.** The site has exactly two transitions (both `0.2s`), no keyframes, no transforms, no scroll animation. Motion exists only to soften hover-state feedback. Any new motion must be subtle, fast, and reversible (see §9).

5. **Intrinsically responsive, one breakpoint.** The grid (`auto-fit`), the container (`max-width`), flex-wrap, and inner measure-widths make the page reflow without media queries. There is exactly one breakpoint (`max-width: 768px`) and it only retunes hero type/padding and nav gap. Prefer intrinsic responsiveness over adding breakpoints.

6. **Tokens are the source of truth (for color).** All color flows from eight `:root` custom properties. Never hard-code a hex for bg/text/border/accent. (Type and spacing are *not* yet tokenized — consistency there is manual; see §3.)

Weights in use: **400 / 500 / 600 / 700** (only these are loaded). Line-heights (all unitless): **1.15 / 1.5 / 1.55 / 1.6 / 1.7**. Reuse from these lists — do **not** introduce a new intermediate size (e.g. `1.1rem`, `2rem`) or an unloaded weight (800/900).

### 3.5 Spacing & radius (de-facto px scale — **not tokenized**)

There is no `--space-*` or `--radius-*` variable; spacing is literal px scattered across rules.

- **Page gutter:** `24px` (constant, even on mobile) — only on `.container`.
- **De-facto spacing steps (px):** `8 · 10 · 16 · 20 · 24 · 32 · 40 · 48 · 50 · 60 · 70 · 80 · 100`. Stay on this set; avoid odd values like `12 / 14 / 18` for layout margins (`14px` appears only inside button padding `14px 28px`).
- **Border-radius scale (two steps only):** `8px` = buttons/controls; `12px` = cards & code block. Do **not** introduce `4 / 6 / 10 / 16px` radii.
- **Card/code internal padding:** `24px` (deliberately equals the page gutter).
- **Flex-gap vocabulary:** `8px` (btn icon) · `10px` (feature h3 icon) · `16px` (cta-group, footer) · `20px` (nav mobile, grid) · `24px` (footer-links) · `32px` (nav desktop). Pick from this set.

> If the site grows, the correct first-principles move is to lift these into `:root` as `--space-*`/`--radius-*` tokens alongside the color tokens — but keep the **same numeric values** so nothing shifts visually.

## 4. Typography

### 4.1 Families & loading

Two faces, one Google Fonts `<link>` (line 12), with `preconnect` hints (lines 10–11) and `display=swap`:

```
family=Inter:wght@400;500;600;700&family=JetBrains+Mono&display=swap
```

- **Inter** — all UI/body text. Stack: `'Inter', -apple-system, BlinkMacSystemFont, sans-serif` (line 33). Ships **exactly weights 400/500/600/700**. Never use 800/900 or italic Inter — they aren't loaded and will synthesize/fall back. If you add a weight, add it to the URL *and* use it; if you stop using one, prune it.
- **JetBrains Mono** — code only. `'JetBrains Mono', monospace` (line 157). Loaded **without a weight axis** → only weight 400 is available. Do **not** bold mono code without first adding the weight to the URL.

> Because the H1 uses Inter via `display=swap`, the headline reflows when Inter arrives. Any layout that depends on H1 geometry (e.g. a rotating headline, §9) must reserve space in `em`/`rem` tied to the H1's own `font-size` so the reserved height survives the font swap without a second CLS.

### 4.2 Role of each size (the hierarchy)

| Element | Spec | Lines |
|---|---|---|
| Hero H1 | `3.2rem` / 700 / lh `1.15` / `margin-bottom 24px` | 88–93 |
| Hero H1 (mobile ≤768px) | `2.25rem` | 304–306 |
| Section H2 | `1.75rem` / 600 / centered (`margin-bottom` 20px or 32px) | 189–194, 213–218 |
| Logo wordmark | `1.5rem` / 700 | 59–64 |
| Tagline | `1.25rem` / 400 / lh `1.6` / `#8b949e` / `max-width 700px` | 99–105 |
| Why-prose | `1.05rem` / 400 / lh `1.7` / `max-width 800px` | 196–206 |
| Feature H3 | `1rem` / 400 (inherited) / flex + 18px icon + 10px gap | 233–239 |
| Button | `1rem` / 600 | 114–124 |
| Nav link | weight 500 | 71–76 |
| Card body `<p>` | `0.9rem` / lh `1.55` / `#8b949e` | 241–245 |
| Footer `<p>` & links | `0.9rem` / `#8b949e` | 271–279 |
| Code `<pre>` | `0.82rem` / lh `1.6` / JetBrains Mono | 156–161 |
| DARPA notice | `0.75rem` / italic / lh `1.5` / `#6e7681` | 290–300 |
| Feature-category eyebrow | `0.7rem` / uppercase / **letter-spacing `0.5px`** / 600 / gold | 247–254 |

Notes that carry brand weight:
- **H2 is 600 (semibold), not 700** — deliberately a step lighter than the hero H1. Reuse `1.75rem/600/centered` for any new section title; the only legitimate variation is `margin-bottom` (20px before prose, 32px before a grid).
- **Feature H3 is intentionally understated** — `1rem`, regular weight. It is differentiated by the leading icon and the gold eyebrow above, not by size or boldness. If it needs more emphasis, prefer weight 500/600 over enlarging.
- **Letter-spacing exists exactly once** (`0.5px` on the uppercase eyebrow) and only *because* the text is uppercase. Do **not** add letter-spacing to mixed-case text — it's nowhere else for a reason.

### 4.3 The hero H1 structure (brand signature)

```html
<h1>Structured evaluation for<br><span>LLM-generated content</span></h1>
```

The pattern is fixed: **line 1 in default light text (`--text-primary`), line 2 in accent gold (`--accent`), split by a manual `<br>`** (not auto-wrap). The `<span>` changes **color only** — it stays 700 / `3.2rem`. When editing the headline:
- Keep the `<br>` so the two-line rhythm survives.
- Keep the gold on the **subject phrase** (the product domain), never on line 1, never on the whole H1.
- Preserve `line-height: 1.15` — looser leading breaks the stacked look.
- If you change the desktop `3.2rem`, re-tune the mobile `2.25rem` proportionally.
- The gold is scoped to `.hero h1 .accent` (re-scoped from the original `.hero h1 span` when the rotator shipped, so the roller's wrapper spans don't turn line 1 gold). Keep gold on the `.accent` subject phrase only — never on a wrapper span or line 1.

> **Implemented:** the hero `<h1>` is now a vertical-roll **rotator** that cycles this signature between two phrasings — "Structured evaluation for / LLM-generated content" and "LLM-based grading for / Human-authored content" — each preserving the gold-subject-line split. See *§9 — Shipped: the hero headline rotator*.

## 5. Layout & spacing

### 5.1 The container primitive

One reusable `.container` is the sole horizontal-layout primitive, used by header, hero, why-section, features, and footer (lines 321, 335, 397, 413, 553):

```css
.container { max-width: 1200px; margin: 0 auto; padding: 0 24px; }
```

**Rule:** never set width/margins on sections directly. Sections are full-bleed bands; nest a `<div class="container">` inside and let it own the `1200px` cap + `24px` gutters.

### 5.2 Content measure-width ladder (inner measures inside the 1200px container)

| Width | Used for |
|---|---|
| `1200px` | Container (full-width feature grids) |
| `960px` | Code block |
| `800px` | Why prose, DARPA legal |
| `700px` | Hero tagline |

Always center with `margin: 0 auto`. Reuse this ladder; don't invent new measures.

### 5.3 Section vertical rhythm (per-section paddings)

| Section | Padding (top / bottom) | Line |
|---|---|---|
| `header` | `20px 0` | 49 |
| `.hero` | `100px 0 60px` (mobile `70px 0 50px`) | 84 |
| `.why-section` | `60px 0 40px` | 185 |
| `.features` | `60px 0 80px` | 210 |
| `footer` | `40px 0` | 259 |

`60px` is the dominant section-top value. When adding a section, match a neighbor's padding rather than inventing a number. Asymmetric top/bottom values are deliberate — preserve them.

### 5.4 Dividers

Every structural divider is **exactly `1px solid var(--border)`** (`#30363d`) — never a different width, color, or a box-shadow. Convention:
- `header` → `border-bottom`.
- `.why-section` / `footer` → `border-top`.
- The hero has **no** border (it flows under the header's bottom rule).
- `.features` has **no** `border-top`; its separation from the why-section is spacing alone.

If you add a section between why and features, give it a `border-top` to keep the hairline cadence.

### 5.5 The one true grid

```css
.features-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(280px, 1fr));
  gap: 20px;
}
```

This is the only CSS Grid on the page. It is responsive with **zero media queries** and tops out at **3 columns at 1200px** (not 4: `floor((1152 + 20) / (280 + 20)) = 3`). New feature cards flow automatically. Keep `auto-fit` + `minmax(280px, 1fr)` + `20px` gap; don't add column overrides in the 768px block. (To get 4-up you'd lower the floor to ~260px — but verify single-column readability on phones first.)

### 5.6 Flexbox map + sticky footer

Everything non-grid is flexbox. The **sticky footer is load-bearing**: `body { display:flex; flex-direction:column; min-height:100vh }` (lines 36–38) paired with `footer { margin-top:auto }` (line 258). Keep both intact when adding sections.

Other flex contexts: header bar (`space-between`), nav (`gap:32px`), `.cta-group` (`gap:16px; justify-content:center; flex-wrap:wrap`), `.btn` (`inline-flex; gap:8px`), `.feature h3` (`gap:10px`), footer bar (`space-between; flex-wrap:wrap; gap:16px`).

### 5.7 The single breakpoint

```css
@media (max-width: 768px) {
  .hero h1 { font-size: 2.25rem; }   /* from 3.2rem */
  .hero    { padding: 70px 0 50px; } /* from 100px 0 60px */
  nav      { gap: 20px; }            /* from 32px */
}
```

That is **all** it changes. The container gutter, the grid, the code block, and cards are intentionally fluid and untouched. **Put any new mobile rule in this same block** — do not scatter new breakpoints. (Known gap: 5 nav links at `20px` gap can overflow narrow phones; there is no hamburger. A future mobile-nav fix belongs in this block.)

## 6. Color & contrast

All text-on-background pairs clear WCAG AA; most clear AAA. Verified ratios:

| Pair | Ratio | Verdict |
|---|---|---|
| `--text-primary` `#e6edf3` on `#0d1117` / `#161b22` / `#21262d` | 16.02 / 14.64 / 12.88 | AAA (bulletproof, any size) |
| `--text-secondary` `#8b949e` on `#0d1117` / `#161b22` / `#21262d` | 6.15 / 5.62 / **4.95** | AA (the `#21262d` case is the thinnest margin — ~10% over the floor) |
| `--accent` `#f0b429` on `#0d1117` / `#161b22` | 10.15 / 9.28 | AAA |
| `--accent-hover` `#f7c948` on `#0d1117` | 12.08 | AAA |
| `#000` on `--accent` (btn-primary) | 11.27 (hover 13.40) | AAA |
| **`.darpa-notice` `#6e7681` on `#0d1117` @ 0.75rem** | **4.12** | **FAILS AA-normal (needs 4.5:1)** |
| `--border` `#30363d` on `#0d1117` / `#161b22` | 1.55 / 1.42 | Decorative only (exempt) |

**Rules:**
- **Do not darken `#8b949e` or lighten backgrounds toward it.** On `#21262d` it is only `4.95:1`. If you ever place secondary text on `#21262d` below `0.9rem`, re-verify ≥ 4.5:1.
- **Fix the DARPA notice** (the one real risk). Either reuse `--text-secondary` `#8b949e` (6.15:1) and drop the bespoke `#6e7681`, or lighten to ≥ `#7d8590`/`#767e88`. At minimum, never make it darker or smaller.
- **Borders** (`1px` `#30363d`) are decorative separators — WCAG 1.4.11 doesn't strictly apply. But `.btn-secondary` relies on its border as its only at-rest boundary; if you want it to meet the 3:1 non-text-contrast bar, lighten that border toward ~`#4a525c` or lean on the `--bg-tertiary` fill.

**Accent-use rules:** gold is foreground-emphasis only — headline span, eyebrow labels, primary CTA, feature-icon strokes, and (recommended) focus rings. Never gold body text, never large gold fills. Keep `#f7c948` paired strictly as the hover/active variant. If a second accent is ever truly needed, make it a desaturated neutral, not a competing hue.

## 7. Components

All components share the token set, the two radii (`8px`/`12px`), and the two fonts. **No component defines `:focus-visible`, `:active`, or `:disabled`** — only `:hover` (see §9 and §11).

### 7.1 Header + nav (lines 48–80, 320–331)
`header`: `padding 20px 0` + `border-bottom 1px solid var(--border)`. Inner `.container` is flex `space-between` / `align-items:center`. `.logo` (line 322): text link, `1.5rem`/700, `href="/"`. `nav`: `display:flex; gap:32px`. `nav a`: `--text-secondary`, weight 500, `transition: color 0.2s`, hover → `--text-primary`. **Header is not sticky.** Five links: Docs, Cookbook, Paper, GitHub, PyPI. Add new nav items as plain `<a>` inside `<nav>`; they inherit gap and hover. Don't make the header sticky without re-checking the hero's `100px` top padding.

### 7.2 Hero (lines 83–112, 334–361)
`.hero`: `padding 100px 0 60px; text-align:center`. Contains the H1 (§4.3), `.tagline` (≤700px, muted, never `--text-primary`), and `.cta-group` (flex, `gap:16px`, centered, wraps). New CTAs go in `.cta-group` and wrap automatically.

### 7.3 Buttons (lines 114–143)
Buttons are **anchors** (`<a class="btn …">`), not `<button>`.

| Class | Spec |
|---|---|
| `.btn` (base) | `padding:14px 28px; border-radius:8px; font-weight:600; font-size:1rem; display:inline-flex; align-items:center; gap:8px; transition:all 0.2s` |
| `.btn-primary` | `background:var(--accent); color:#000`; hover → `background:var(--accent-hover)` |
| `.btn-secondary` | `background:var(--bg-tertiary); color:var(--text-primary); border:1px solid var(--border)`; hover → `border-color:var(--text-secondary)` |

Rules: keep **one `.btn-primary` per view**. Icon buttons use the base `gap:8px` and a `20×20` `stroke="currentColor"` SVG so the icon tracks text color. Primary text stays `#000` on gold (never `--text-primary`). Migrate new buttons from `transition: all 0.2s` to explicit `transition: background 0.2s, border-color 0.2s` (cheaper, scoped). Add a `:focus-visible` before shipping (see §11).

### 7.4 Code block (lines 146–181, 363–392)
`.code-block`: `background:var(--bg-secondary); border:1px solid var(--border); border-radius:12px; padding:24px; max-width:960px; margin:50px auto 0; text-align:left` (resets the hero's centering). `pre`: JetBrains Mono `0.82rem` / lh `1.6` / `overflow-x:auto`. Manual span highlighting only (§3.3). Keep the nested width hierarchy (960px < 1200px container; wider than the 700px tagline).

### 7.5 Why-section (lines 184–206, 396–410)
`.why-section`: `padding 60px 0 40px; border-top 1px solid var(--border)`. `h2`: `1.75rem`/600/centered. `.why-content`: `max-width:800px; color:var(--text-secondary); line-height:1.7; font-size:1.05rem`; paragraphs `margin-bottom:16px`. This is the only prose section — keep copy within `800px` and the relaxed `1.7` leading. Use `<strong>` (renders Inter 700) for inline emphasis, sparingly.

### 7.6 Features grid + cards (lines 209–254, 416–541)
Card surface recipe (shared with the code block): `background:var(--bg-secondary); border:1px solid var(--border); border-radius:12px; padding:24px`. Internal rhythm: `.feature-category` (eyebrow, `margin-bottom:16px`) → `h3` (`margin-bottom:10px`, flex + 18px icon + 10px gap) → `p` (`0.9rem`/lh `1.55`/`#8b949e`).

To add a feature, copy the exact skeleton:
```html
<div class="feature">
  <div class="feature-category">Robustness</div>   <!-- one of the 5 categories -->
  <h3>
    <svg width="18" height="18" viewBox="0 0 24 24" fill="none"
         stroke="var(--accent)" stroke-width="2"> … </svg>
    Feature Name
  </h3>
  <p>Two–three short declarative fragments dense with named methods/metrics.</p>
</div>
```
Keep card descriptions to 2–3 lines (suits the compact `0.9rem`). Don't set explicit column counts — the grid reflows itself.

### 7.7 DARPA notice (lines 290–300, 543–547)
`font-size:0.75rem; color:#6e7681; font-style:italic; line-height:1.5; max-width:800px; centered; margin-top:48px`. The dimmest/smallest text on the page. **This is compliance text** — preserve the disclaimer sentence and `Agreement No. HR00112520300` verbatim; never paraphrase, trim, or promote it into a badge. Keep `author` singular (ties to the single-author footer). Fix only its contrast (§6).

### 7.8 Footer (lines 257–288, 552–561)
`footer`: `margin-top:auto` (sticky anchor), `padding:40px 0`, `border-top 1px solid var(--border)`. Inner `.container`: flex `space-between`, `flex-wrap:wrap`, `gap:16px`. `footer a`: `--text-secondary`, hover → `--text-primary` (same as nav). `.footer-links`: flex `gap:24px`. The year uses an inline `<script>document.write(new Date().getFullYear())</script>` — the **only JS on the page**. Keep a dynamic year; recommend migrating off `document.write` (see §11).

## 8. Iconography

A single, tight inline-SVG system. **No raster imagery anywhere.** Eleven icons, all Feather/Lucide line glyphs.

### The icon contract (all 11 icons obey)
```
viewBox="0 0 24 24"   fill="none"   stroke-width="2"
```
Drawn only from stroke primitives (`<path>`, `<line>`, `<polyline>`, `<circle>`). Any new icon **must** be a 24×24, `fill=none`, `stroke-width=2` line icon from [feathericons.com](https://feathericons.com) / [lucide.dev](https://lucide.dev). Never a filled, duotone, or different-grid glyph; never change stroke-width per-icon.

### Two roles (color + size)

| Role | Size | Stroke | Where |
|---|---|---|---|
| Hero/CTA icons | `20×20` | `stroke="currentColor"` (inherits button text color) | lines 343, 351 |
| Feature-card icons | `18×18` | `stroke="var(--accent)"` (always gold) | 9× from line 419 onward |

**Rule:** an icon inside an interactive/text element uses `currentColor`; a decorative feature/section accent uses `var(--accent)`. Never hard-code `#f0b429` in markup. Don't invent intermediate sizes (`20` = CTA, `18` = feature). Keep the icon-label gap matched to its container (`8px` in `.btn`, `10px` in `.feature h3`). Don't scale below ~16px or the 2-unit stroke clogs.

### Known issues to keep consistent
- The **file-text** glyph is reused for both "Paper" (CTA) and "Few-Shot Calibration". Acceptable; if you want each feature unique, swap Few-Shot to a distinct 18px `var(--accent)` glyph.
- Icons currently omit `stroke-linecap`/`stroke-linejoin` (render with sharp `butt`/`miter` defaults, slightly crisper than canonical Feather). **Pick one convention and apply to all** — either add `stroke-linecap="round" stroke-linejoin="round"` everywhere, or leave them off everywhere. Don't mix.
- All 11 SVGs lack `aria-hidden` — add `aria-hidden="true"` (and `focusable="false"`) since each sits beside a text label (see §11).
- Gaps worth filling on-brand: a favicon (inline-SVG/data-URI to avoid a request) and an OG/share image — both should use the same gold-on-`#0d1117` palette.

## 9. Motion & interaction

**The site is deliberately restrained, and that restraint is the brand.** There is exactly **one** intentional animation — the hero headline rotator (below) — built to the rules in this section. Everything else is hover-feedback only. Document any new motion carefully.

### Baseline motion vocabulary (everything except the hero rotator)
- **Two** hover transitions: `nav a { transition: color 0.2s }` (line 75) and `.btn { transition: all 0.2s }` (line 120).
- Easing is the implicit default `ease` outside the rotator; no other custom curve.
- Four `:hover` rules. Three animate (nav link color, primary-button background, secondary-button border). **`footer a:hover` does NOT animate** — `footer a` declares no transition, so it snaps. This is an inconsistency: add `transition: color 0.2s` to `footer a` to harmonize it with nav.

### Shipped: the hero headline rotator (reference implementation)
The hero `<h1>` cycles between two two-line phrasings — "Structured evaluation for / LLM-generated content" and "LLM-based grading for / Human-authored content" — via a vanilla **vertical roll**. It is the canonical example of "new motion done right" and the only `transform`/JS-driven motion on the page.
- **Markup:** `.hero-headline` holds a visually-hidden static accessible name (`.sr-only`) **plus** an `aria-hidden` `.roll-viewport` → `.roll-track` containing **three** `.roll-phrase` blocks `[A, B, A′]` (A′ duplicates the default). Each phrase keeps its manual `<br>` and the gold `.accent` subject line.
- **Mechanism (always-up, invisible snap):** the track only ever rolls **up** (`translateY` step 0→1→2); on reaching the duplicate `A′` it snaps back to `A` with transitions off — invisible because both render the default. No per-tick DOM reordering (this is what makes it robust — no reset-desync).
- **Timing:** `--roll-ms: 650ms` / `--roll-ease: cubic-bezier(0.22, 1, 0.36, 1)` (gentle ease-out), asymmetric dwell `DWELL = [5200, 2600]ms` so the default shows ~2× the alternate. The JS constants mirror the CSS custom properties — **keep them in sync**.
- **Gray-on-exit:** the outgoing `.roll-phrase` gets `.is-leaving`, transitioning its color (and the gold `.accent`) to `--text-secondary` + `opacity 0.55` over the roll, so the departing title desaturates as it rises.
- **CLS:** the stage height is JS-measured (the `max` of both phrases) after `document.fonts.ready` and re-measured on resize; the `em`-based fallback (`2.3em`) keeps the no-JS / reduced-motion state to one line-pair. **Verified zero layout shift.**
- **Accessibility:** the rotator is `aria-hidden`; the `.sr-only` child gives the `<h1>` one stable accessible name. Reduced-motion is honored in **both** CSS (`transform`/`transition: none`) and JS (the loop never starts; a runtime `change` listener stops it). The loop pauses on `visibilitychange` (tab hidden) and resumes on the default phrase. The rotator is never focusable.
- **Accent footgun (resolved):** because the rotator adds wrapper `<span>`s, the gold was re-scoped from `.hero h1 span` to `.hero h1 .accent`. Keep gold on `.accent` only.

### Rules for any NEW motion

1. **Subtle, fast, eased.** Reuse `0.2s` as the canonical hover/interaction duration; entrances/cross-fades stay within `0.2–0.4s`, `ease-out` (decelerating, "calm"). The one sanctioned exception is a **deliberate, infrequent content rotation** (the hero headline rotator), which may run up to ~`0.65s` with a gentle ease-out (`cubic-bezier(0.22, 1, 0.36, 1)`) because it is a content change, not feedback. Never `ease-in`, never bouncy/overshoot curves.
2. **Scope the property.** Prefer `transition: opacity 0.3s` / `transition: color 0.2s` (the line-75 pattern) over `transition: all 0.2s` — predictable and cheap. Never transition layout properties. Prefer compositor-only properties (`opacity`, `transform`) over paint-heavy ones (`filter`, which the page has never used).
3. **MUST honor `prefers-reduced-motion`.** There is **no** such block today — it must be authored fresh and is a non-negotiable acceptance criterion for any motion PR. Add the blanket guard near the top of `<style>`:
   ```css
   @media (prefers-reduced-motion: reduce) {
     *, *::before, *::after {
       animation-duration: 0.01ms !important;
       animation-iteration-count: 1 !important;
       transition-duration: 0.01ms !important;
       scroll-behavior: auto !important;
     }
   }
   ```
   The reduced-motion path for any cycling/entrance effect must show a **single static state** (or opacity-only cross-fade), never translate/scale. Any JS rotator must *also* check `window.matchMedia('(prefers-reduced-motion: reduce)').matches` and simply not start (CSS alone can't stop a `setTimeout` loop), and should re-evaluate on the media query's `change` event.
4. **MUST NOT cause layout shift (CLS).** Any element whose content changes (e.g. a rotating headline) must reserve space sized to the **tallest/longest** value. The robust technique is to **stack both states in one grid cell** (both children at `grid-area: 1 / 1`) so the container auto-sizes to the taller child — not `position: absolute` + `min-height`, which only reserves the default state and lets a longer alternate overlap the content below. The hero H1 is `3.2rem`/lh `1.15` (→ `2.25rem` ≤768px), so variance is large — reserve it, and verify *both* states render at the same line count at the mobile size.
5. **`aria-live` for changing text — used narrowly.** Don't make the page's only `<h1>` a self-mutating `aria-live` region (it spams announcements and destabilizes the document outline). Prefer: `aria-hidden="true"` on the animated rotator + one **visually-hidden static `<h1>`/label** carrying the canonical phrase, for a stable accessible name. If a live update is genuinely wanted, scope `aria-live="polite"` `aria-atomic="true"` to just the changing region and toggle `aria-hidden` on the inactive node so AT reads exactly one phrasing. Never `role="alert"`/`aria-live="assertive"` on decorative rotating text. The animated element must never be focusable (no `tabindex`); set `pointer-events:none` on hidden states.
6. **No ambient/infinite animation.** No pulsing accents, marquees, or animated gradients — they break the calm research-tool tone. Animate SVGs only as one-shot hover stroke/color shifts, never perpetually. A text rotator is allowed but should **pause while the tab is hidden** (`document.visibilitychange`) and resume cleanly on the default state.
7. **Entrance motion, if added:** a single `@keyframes` doing `opacity 0→1` (+ optional `translateY ~8–12px`), `0.3–0.4s ease-out`, triggered once via IntersectionObserver rather than all-at-load.

### Focus motion
When you add `:focus-visible` (§11), mirror the hover vocabulary: animate it at the same `0.2s` via a color/border fade — never with transforms or scale.
